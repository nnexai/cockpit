# Cockpit decisions in force

Current rules are grouped by behavioral contract: conditions, limits and caveats of one rule share a bullet. [Architecture](CONTEXT.md), [code navigation](CODE_GUIDE.md), [configuration](docs/configuration.md) and [historical verification](docs/verification-log.md) have separate roles. Links locate applicable owners; procedural delivery/evidence policies and explicitly unverified requirements are not claims of runtime enforcement.

## Herdr authority & compatibility

- Herdr owns sessions, Spaces/workspaces, tabs, real-terminal existence/membership, PTYs, processes, focus identity and agent state; Cockpit caches this authority without a competing live registry, and Space context records relevance, not ownership. [Owner](crates/cockpit-herdr/src/cli.rs). Rationale: One live authority prevents divergent lifecycle state.

- Use supported socket methods for persistent state/streams; require protocol 22, schema 1 and every required method, failing closed on mismatch rather than using display-version patch allowlists. [Owner](crates/cockpit-herdr/src/schema.rs). Rationale: Capabilities come from the inspected schema.

- Command/popup discovery requires identity-checked generation-1 full surfaces and mandatory codecs; negotiate endpoint.surface-delta.v1 only when advertised with compatible bounded decoding, otherwise retain full surfaces. [Owner](crates/cockpit-herdr/src/shell_wire.rs). Rationale: An optional codec cannot weaken admission.

- Before accepting shell deltas, match boot/peer identity, baseline projection/surface revisions and dimensions; validate cells in reusable bounded scratch without retaining them. Popup patches require matching terminal/grid and corresponding cell updates; replacements establish new grids. [Owner](crates/cockpit-herdr/src/shell_wire.rs). Rationale: Metadata alone cannot authorize a popup.

- Keep unsupported, disconnected, timeout, malformed and identity errors explicit: shell_unsupported never permits guessed bindings, retired commands reject command_not_available, invalid targets command_target_invalid, and stale popup attachment popup_not_open. [Owner](crates/cockpit-herdr/src/cli/shell.rs). Rationale: Unavailable capability is not dispatch permission.

- Bootstrap from an authoritative snapshot and ordered events; resnapshot/rebind on gaps, identity changes, reconnect or stale state, and clear old subscriptions/renderers/selections on session switch. ACKs and later HTTP arrival do not supersede ordered focus/control state. [Owner](src/app/session/sessionStore.ts). Rationale: Arrival order is not state authority.

- Keep tab placement only in memory, keyed by session/server instance/tab: same-instance resync preserves it, changed instance starts fresh. Ignore Herdr rectangles/zoom hints; local drag/divider/swap/zoom sends no pane_resize/pane_swap/pane_zoom, though fitted control attachments resize PTYs. [Owner](src/app/layout/tabLayoutStore.ts). Rationale: Presentation is separate from terminal membership.

- First load balances stable pane-ID order; external terminals enter at the full-height right edge with share 1/(existing leaves+1), including zoom-hidden leaves. Place Cockpit-created terminals beside the acted-on leaf only from a validated creation receipt. [Owner](src/app/layout/splitTree.ts). Rationale: Focus or snapshot differences cannot attribute creation.

- Follow changed external Space/tab/pane focus unless it echoes current local intent, restoring zoom if needed; unchanged focus never steals viewer selection. Viewer selection sends no Herdr focus request; leaf selection, server focus, control ownership and DOM focus remain distinct. [Owner](src/app/layout/reconcile.ts). Rationale: Repeated observations must not override local intent.

- Only confirmed tab/final-real-terminal loss retires layouts and local viewers/Browser/widgets; loading, stale or disconnected state is not loss. Browser association work is discarded, while viewer batches remain run-local until owner reset. [Owner](src/app/layout/browserLifecycle.ts). Rationale: Uncertain observation grants no cleanup authority.

- Order agents blocked, done, working, idle, unknown, newest state change first; this is client presentation matching Herdr TUI priority, not API workspace order, agent_panel_sort or plugin agent views. [Owner](src/app/sidebar/Agents.tsx). Rationale: Presentation ordering must not impersonate server state.

## Terminal attachment & input

- Herdr owns PTYs, models and scrollback; xterm renders/captures input. Painted active-tab terminals attach control-only at fitted grid/cell pixels, never observe/downgrade; input additionally needs DOM focus, confirmed Herdr focus and owned control. [Owner](crates/cockpit-herdr/src/terminal_wire.rs). Rationale: Rendering alone cannot authorize input.

- Require a full first frame and consecutive subsequent sequences, including full repaints; never reset xterm for a full ANSI baseline. Reconnect needs a new baseline; one uninterrupted reader provides bounded buffering and deterministic shutdown. [Owner](crates/cockpit-herdr/src/terminal_wire.rs). Rationale: Continuous framing preserves terminal state.

- Tab switches prepare painted target attachments before Herdr focus, gated by the focused pane’s first frame or 300 ms, with no gate if none are painted; retain outgoing attachments until swap paint. Fresh membership, not geometry, determines eligibility; Herdr resizes on control attach and restores TUI size on disconnect. [Owner](src/app/session/focusCoordinator.ts). Rationale: The incoming PTY must fit before focus changes.

- Move DOM focus to the incoming selected terminal only after paint and confirmed control, never to its hidden attachment. Hidden tabs, zoom leaves and Library detach without stopping processes/scrollback; Files/Review state persists and hidden Browser releases captures without closing its session. [Owner](src/app/TerminalPane.tsx). Rationale: Visibility and process lifetime are independent.

- Use raw Input for ordinary text/binary bytes and bare LF for Shift+Enter; use AttachScroll for wheel/page and structured cell-coordinate AttachMouse only under MouseCapture demand. Never substitute raw SGR; mode-off/Shift-drag retain selection, without idle hover/pixel forwarding. [Owner](crates/cockpit-herdr/src/terminal_wire.rs). Rationale: Herdr chooses the application mouse encoding.

- Keep graphics parked: consume known auxiliary messages without exposing graphics payloads or disconnecting usable text terminals, and do not load the image addon. Local Kitty keyboard support is not end-to-end enhanced-reporting acceptance. [Owner](src/app/TerminalPane.tsx). Rationale: Unsupported imagery must not break text.

- Attach/resync/retry failures leave resources intact and visible with stale/disconnected status and recovery; inspect authoritative state before retrying uncertain mutations. Name evidence paths precisely: physical attach, xterm wheel, structured AttachMouse or CLI-injected SGR. [Owner](src/app/TerminalPane.tsx). Rationale: One input-path observation cannot prove another.

- Render the singleton popup centered over the unchanged split tree using server title/cell/percentage hints and validated direct popup transport. Keep painted underlay attachments, make it inert and gate input even during pending invocation; Esc/Enter/Tab/prefix keys belong to the program. [Owner](src/app/ServerPopup.tsx). Rationale: A popup must not reflow or control underlying panes.

- Only fresh popup metadata closes/replaces it; stale/disconnected state retains disabled input/status/retry. On closure prefer the eligible selected terminal, then an available opener, then tab chrome; delayed restoration must not steal focus or mutate Herdr focus. [Owner](src/app/ServerPopup.tsx). Rationale: Staleness is not closure.

- The active 120×40 shell subscription required for command/popup metadata can resize unattached panes and concurrent Herdr TUI; it is not passive or geometry-neutral. Direct attachments protect fitted Cockpit PTYs without changing local splits. [Owner](crates/cockpit-herdr/src/shell_wire.rs). Rationale: Document the chosen API’s real side effect.

## Keyboard

- Keep platform-independent Ctrl+B prefixes and Herdr-default action meanings or leave them unbound; Cockpit-only actions use free keys. The quick switcher is the explicit direct-chord exception: Ctrl+K on Linux/Windows, Cmd+K on macOS, available from terminals and editors outside modals. Omit Herdr-only s/q/e/[/o/Shift+G/Shift+R; cycle Ctrl+B Tab/Shift+Tab in local visual order. Static registry drives Commands/tooltips/generated docs, not runtime plugin entries. [Owner](src/app/input/shortcuts.ts). Rationale: One registry keeps local discoverability accurate.

- Discover generic shell/pane/popup/plugin commands, opaque IDs, aliases and configured prefixes from identity-checked live projection; reload replaces retired bindings. Invoke only currently advertised actions against confirmed Herdr focus and revalidated membership, never uncertain-result replay. [Owner](src/app/input/herdrBindings.ts). Rationale: Advertisements are revocable dispatch authority.

- Outside editors/dialogs, direct custom bindings precede viewer keys; configured Herdr prefixes coexist with Ctrl+B, and shared Ctrl+B custom aliases win collisions. Hide shadowed local hints; reserve literal Ctrl+B Ctrl+B and Herdr-prefix double-prefix passthrough before custom lookup. [Owner](src/app/input/keymap.ts). Rationale: Collision policy must preserve literal program input.

- Terminal/inline Browser claims stay narrow: direct quick-switch Ctrl+K (Cmd+K on macOS), prefixes/custom bindings, clipboard Ctrl+Shift+C/V (Cmd+C/V on macOS) and Shift+Enter; other unbound Tab/Shift+Tab/Alt/function/Ctrl keys reach content. Recognize Browser prefixes on its surface, not URL/note editors; popup routing yields entirely. [Owner](src/app/input/keymap.ts). Rationale: Workbench shortcuts must not trap content keys.

- Local modals own focus; delayed pane autofocus yields, and portalled inputs cannot select their Files pane through bubbling. Viewer handlers require DOM containment and yield to editable/modal focus. [Owner](src/app/input/modal.ts). Rationale: React ancestry is not keyboard ownership.

- Pane-scoped prefixes close Library first and act on the selected leaf of any kind: splits create terminals, focus/cycle/swap/zoom use local placement. Viewers cannot cross tabs/Spaces; Esc cancels drag or restores zoom only on chrome, otherwise belongs to content. [Owner](src/app/shell/useWorkbenchActions.ts). Rationale: Commands must respect the selected surface.

- Library open focuses selected/first tree row; close by any route restores a connected sidebar invoker, else an eligible reattached terminal or still-selected graphical origin, else safe chrome. Closing changes DOM focus only, never Herdr focus. [Owner](src/app/shell/useWorkbenchInput.ts). Rationale: View navigation must preserve explicit focus ownership.

## Workspace & filesystem ownership

- Setup is input-bound and plan-driven: Open accepts exact validated plain/nested directories, never initializes Git, switches branches, clones or requires repository selection; optional Git discovery is metadata only. Stale plans need a fresh start; provider links cannot choose a local repository. [Owner](crates/cockpit-core/src/projects/plan.rs). Rationale: Artifact identity is not checkout authority.

- Cockpit owns operation records, Library, Notes and context selections, not borrowed opened directories. Setup creates no companion copies; configured actions need no per-operation checkbox but never set Herdr trust_repository. Preserve operation identity across closed dialogs/uncertain dispatch and reconcile, not duplicate setup. [Owner](crates/cockpit-core/src/projects/execute.rs). Rationale: Ownership comes from exact receipts.

- Open/Create keeps only Herdr's default root terminal and records its tab/pane receipt; setup never adds a context tab. Initial worktree/open panes and TUI-created terminals cannot be retrofitted with Cockpit context environment. Use `cockpit-cli context --current` for Library and selected paths; supported environment for later Cockpit-created terminals and orchestration launches remains separate. Existing Herdr metadata stays inherited; never silently close or replace the initial pane. [Owner](crates/cockpit-herdr/src/cli/projects.rs). Rationale: Unsupported environment injection cannot justify extra processes or process replacement.

- Automatic teardown requires owned creation evidence and fresh resource checks. Explicit manual removal instead uses the selected Space's freshly verified linked, non-primary checkout, regardless of missing/stale setup ownership records. Clean removal requires confirmation; dirty removal shows the affected paths and requires `DISCARD AND REMOVE` with the reviewed path fingerprint. Endpoint/Space/path changes invalidate the review, and pending or uncertain removals reconcile rather than replay. Main checkouts, unrelated folders, Library and Notes remain untouched. [Owner](crates/cockpit-core/src/projects/teardown.rs). Rationale: The local operator must be able to remove their worktree without reconstructing historical ownership.

- Keep reads bounded/rooted/no-follow/identity-checked; revalidate roots and source identity before mutations/comments. Selected extra repositories must still belong to the configured catalog and pass fresh filesystem/Git checks; revocation preserves diagnosed selections, while fresh own-checkout authority is separate. [Owner](crates/cockpit-core/src/context.rs). Rationale: Selection is relevance, not access control.

- Pull fetches without mappings changing local branches, then fast-forwards only, never rebase/merge/autostash. Push uses explicit branch-to-existing-upstream refspec, never force/mirror/upstream setup; preserve normal credentials/URL aliases and never expose remote URLs in status/diagnostics. [Owner](crates/cockpit-core/src/space_git_action.rs). Rationale: Status actions must not rewrite Git intent.

- Row actions target their explicit Space without selecting it; Commands targets selected Space/worktree. After reservation, recheck fresh Herdr checkout, filesystem/Git identity, branch/upstream/effective destination; pane-folder status gives no write authority and counters mean last fetch. [Owner](crates/cockpit-core/src/space_git_action.rs). Rationale: Queued work must not silently retarget.

- Confirmed Git outcomes refresh status and show brief row-local success; refusal/not-run/unknown remains inline, echoed elsewhere only if offscreen. Unknown keeps Pull/Push disabled until dismissed; inspect ambiguous spawned/transport failures, never retry or claim no change. [Owner](src/app/sidebar/SpaceGitAction.tsx). Rationale: Uncertainty must remain actionable and honest.

## Supervisor orchestration

- The liaison conversation is primary, using its real Herdr terminal and one attachment. Its compact read-only task rail keeps the same placement for open and all-Done work; completed tasks use the existing disclosure while work remains and appear directly when all tasks are done. The rail disappears only when there are no tasks. Optional fullscreen Overview keeps Board/Graph visible beside the selected task's shared history; narrow views stack detail below instead of replacing the overview. Close/Escape restores the originating task's focus and scroll; Escape without detail returns to the conversation. Start reuses/reattaches the project root before creating one. Human decisions, worker coordination and cleanup blockers go through the liaison; no worker-answer, task-editing, global Activity/Diagnostics/archive, attention queue or operational retry UI. History projects existing attempts, reports, answers, integration and resource records, not a new event store; generic update times never masquerade as acceptance times. [Owners](src/app/supervisor/useLiaison.ts): `SupervisorTasks.tsx`, `TaskHistoryDetail.tsx`, `taskHistory.ts`, `SupervisorView.tsx`, `SupervisorGraph.tsx`. Rationale: Keep existing observational surfaces consistent without replacing the harness conversation.

- `run done` is worker-only (`actor_forbidden` for a root). The liaison finishes batches in conversation, stays Active and serves later tasks on the same project root. Low-level root Result reports are diagnostic and do not close its attachment/session or authorize retirement. [Owner](crates/cockpit-host/src/cli_orchestration/mod.rs). Rationale: A task batch is not the lifetime of the human's liaison.

- Canonical task title/description/relationships/checklist/check live only in orchestration/tasks/<root_id>.md with stable UUID markers; Task.body is read-only full continuation. Edits splice description/core-owned spans while preserving protected metadata, interleaved prose and neighbors; unmarked/duplicate/ambiguous source needs diagnosis, not guessed mutation. [Owner](crates/cockpit-core/src/orchestration/tasks_md.rs). Rationale: One Markdown authority prevents copied task stores.

- TaskAssign journals one stable UUID, canonical item and root-inbox pointer across documents; submitted title/description persist only until both commit. Authoring alone is not assignment; exact-byte task/document revisions fence writes and recovery preserves external edits without rollback. [Owner](crates/cockpit-core/src/orchestration/assignments.rs). Rationale: Cross-document intent must be recoverable.

- Durable tasks are independent of replaceable execution attempts. Lanes derive canonical dependencies, checked state and current execution: Blocked, Ready, Working, Review and Accepted (UI Done); Starting is an attempt badge. Initialized is diagnostic only; runtime idle/done, succeeded Result or completed steps do not accept a task. Parentage remains independent of Space. [Owner](crates/cockpit-core/src/orchestration/projection.rs). Rationale: Task purpose, attempt status, reporting and completion are different facts.

- First-continuation metadata permits at most 32 raw depends_on edges and one immutable follow_up_of. Only canonically checked prerequisites satisfy work; start, dispatch, new effects and acceptance recheck the affected graph, blocking malformed/missing/duplicate/cyclic components while healthy independent work stays runnable. [Owner](crates/cockpit-core/src/orchestration/dependencies.rs). Rationale: Prerequisites cannot be inferred from runtime success.

- Canonical dependencies do not prove input materialization. Same-project/repository accepted Code needs the frozen immutable attempt base to contain exact original output head/commits OR exact currently validated Integrated target/mapped commits with passed target checks. An explicit base may qualify; changed HEAD cannot retarget after proof. Missing input stays queued as deduplicated `dependency_input_not_materialized`, waking on refs/integration even if old resources are gone. Publication rechecks accepted Result/task/source/integration and candidate fences. Cross-repository/conceptual/manual-checked-without-source edges skip unrelated Git proof; NonCode Result/artifact references remain retained and read-only, never inferred published/deleted. Rationale: Dispatch actual predecessor output, including proven adapted integration.

- ExistingSpace/Open input dispatch never retargets the mutable checkout. Fresh clean post-setup HEAD/input proof reserves `base_commit`; immediate pre-release HEAD/clean/proof reinspection and Domain release CAS fence the reserved SHA and current accepted prerequisites. Changes hold the launch instead of releasing a stale writer. Rationale: A mutable placement still needs an immutable named dependency boundary.

- Missing follow-up source is a nonblocking provenance warning, never capability revocation. Relationship writes fence task and document revisions. Direct TaskUpdate relationship edits during an open attempt permit only strict removal of positively parsed edges; Working TaskScopeUpdate instead permits met-prerequisite additions/removals but rejects newly unmet prerequisites. Same-principal/same-UUID/same-payload create replay is inert; changed payload under that key conflicts. [Owner](crates/cockpit-core/src/orchestration/dependencies.rs). Rationale: Provenance and runnable dependencies have different authority; scope coordination is not a blanket Working freeze.

- Stable step UUIDs identify managed tails or already tracked externally edited forests; leaf checks derive Open/Partial/Done and progress. Explicit subtree checks/moves are atomic and preserve subtree IDs/order without accepting tasks; removing last child keeps Done/Open and turns Partial Open. [Owner](crates/cockpit-core/src/orchestration/steps.rs). Rationale: Checklist progress is a projection, not acceptance.

- Checklist limits are 64 rows, depths 0–4, 200 Unicode title scalars, 16 KiB continuation and 8 MiB document. Numeric overflow stays readable with safe checks/shrinking; malformed identities/structure and ambiguous unmarked protected source stay read-only with unavailable progress. [Owner](crates/cockpit-core/src/orchestration/steps.rs). Rationale: Bounded authoring must preserve external Markdown.

- The active credentialed supervisor manages and writes canonical tasks throughout its own root, including a current worker's checklist; Working content updates retain task/document CAS and coordinate the same worker through the scope-update journal. A worker may read other tasks/runs in that root but may author only its own current Working assignment. Role, root, attachment epoch, canonical owner and pinned generation are revalidated under the mutation lock. Agent read projections exclude other roots, sibling private inbox bodies and launch capability bytes; operator/UI observation remains distinct. Labels, telemetry and physical presence grant no semantic ownership. Accepted tasks remain read-only. [Owners](crates/cockpit-core/src/orchestration/mutate/tasks.rs), [credentialed reads](crates/cockpit-core/src/orchestration.rs). Rationale: Supervisor authority and worker collaboration must not become sibling write authority or capability disclosure.

- Root-authorized TaskSchedule retains durable operation identity, scope, brief, placement and cleanup policy without provisioning blocked workers. It persists across root attachment/credential rotation until acceptance/cancellation. Dispatch validates the immutable schedule receipt principal and exact root plus current active root binding, then rechecks dependencies/capacity under lock—not the old credential lifetime. Revoked callers remain rejected; cancelled/accepted schedules cannot replay to reauthorize work. Default `max_parallel` is 4; WorkerStart remains immediate fenced delegation and context atomically claims pending generations. [Owner](crates/cockpit-core/src/orchestration/mutate/runs.rs). Rationale: Durable scheduling must survive liaison recovery without resurrecting revoked authority.

- Corrected TaskSchedule may atomically supersede one proven never-started, effect-free PlanFailed attempt and replace its authorization after canonical revision checks. Existing supersession revokes credentials and fences generations; started, uncertain or physically recorded attempts remain protected. Reconcile is not a planning-correction action. [Owner](crates/cockpit-core/src/orchestration/mutate/runs.rs). Rationale: A rejected plan must not require cancellation/unassignment rituals or create another writer.

- Private active credentials bind agent principal/run/root/role/attachment epoch and the worker's issued task generation; scoped agent mutations and replay retain current-generation checks. Actual conversation metadata is optional for ordinary coordination and validated when supplied. Explicit local CLI `--operator` management uses named root/task/run targets and ignores ambient job credentials and stale attachment/conversation metadata; it is not an implicit fallback or a worker impersonation mode. Operator starts, schedules, replacement, unassign, acceptance, resource release and cleanup remain subject to the actual target and operation-state checks, not an owning-supervisor capability. Fresh physical evidence separately fences terminal effects and cleanup; widgets grant no authority. [Owners](crates/cockpit-host/src/cli_orchestration/context.rs): core `orchestration/credentials.rs`, `mutate/runs.rs`. Rationale: Stale autonomous writers stay fenced without blocking the trusted local operator.

- `run context` activates an unbound issued capability and returns role/run/root/task/generation/inbox context without requiring conversation flags. Actual metadata or explicit conversation flags, when present, retain conflict checks; worker activation atomically claims the authorized vacant generation. The credential UUID is the implicit registration operation ID. Current claim/run/generation replay is inert; conflicting metadata or revoked generation fails without a new-operation retry. No capability means no self-adoption. [Owner](crates/cockpit-host/src/cli_orchestration/context.rs). Rationale: Activation must neither invent authorization nor resurrect an old attempt.

- The active owning Root credential or explicit local operator may unassign/replace under the current run/generation fences. Atomic replacement preserves task/history, old dirty work/resources/claims and source identity. Typed `ReplacementSource` selects committed GitHead worktree or no-copy Directory attempt while retaining the original project/context. Same-checkout reuse requires precise reboot or exact drained owned-runtime proof plus registered resources and fresh Herdr inventory—not main-process exit/universal absence. Transfers retain old attachment history; schedule cancellation leaves attempts untouched. [Owner](crates/cockpit-core/src/orchestration/mutate/runs.rs). Rationale: Replacement must work for Git and Directory projects without stealing old data.

- Directory replacement exclusively creates a private `state_root/orchestration/attempts/<run_id>` with distinct `OwnedAttemptDirectoryIdentity { creation_operation_id, root, device, inode }` tied to the immutable existing creation journal. No source copy, unreceipted EEXIST adoption, manifest/sentinel, redundant UUID or startup machine-ID prerequisite; later Space binding cannot change directory identity. Original project/context/source and old claims/resources remain; source access is read-only by instruction, not a sandbox. Retirement requires accepted/retired/drained proof and an EMPTY directory. Nonempty unique outputs stay `outputs_kept` until durable publication/move; NotApplicable never authorizes recursive deletion, and superseded/cancelled/failed directories remain retained. Rationale: Preserve unique outputs without weakening scope-machine/boot/released-claim destruction proof.

- Route explicit repository/Open/Space targets from configured or actual forge-origin evidence, never supervisor cwd/current Space. Prefer owned SpaceWorktree for Git workers, including read-only research, to permit safe terminal retirement. Scheduled Open paths matching exactly one fresh Git Space and verified repository/checkout identity resolve to that Space's isolated worktree; Directory, ambiguous and mismatched targets retain their original contract. Explicit ExistingSpace remains deliberate borrowed reuse. Default base is the source checkout's immutable HEAD unless explicit; preserve project identity and direct context paths, never retarget a launched writer. [Owner](crates/cockpit-core/src/orchestration/dispatch.rs). Rationale: Placement binds the actual source project without stranding ordinary workers in primary Spaces.

- A root Directory/Open launch without an explicit source Space resolves transport staging once before LaunchIntent from `RuntimeView.focused_workspace_id`, available only for one fresh authoritative Herdr workspace `focused` flag, and persists `staging_workspace_id`. Missing/ambiguous staging reports `staging_space_required`, never bootstraps an uncontained shell. This root-only transport fallback cannot route workers or infer cwd/UI focus; UI ExistingSpace start and explicit worker project source remain unchanged. [Owner](crates/cockpit-core/src/orchestration/dispatch.rs). Rationale: Preserve the user's Space/focus without creating layout resources just to stage launch.

- Orchestration checkout preparation is filesystem-only, preserving operation journals and exact physical worktree/branch proof; borrowed directories acquire no Git/mkdir/delete authority. Bind the moved Space only from fresh exact endpoint/session/generation, new-not-prior/source workspace, one tab/pane, terminal and cwd evidence. Retained bind intents are idempotent; unknown Git creation without proof is never adopted/replayed. Saved source Library IDs/repositories select existing paths without copies or a context shell. Standard user Open/Create setup is unchanged. [Owner](crates/cockpit-core/src/projects/prepare.rs). Rationale: One scoped terminal needs no extra Herdr setup shells.

- Launch is harness-neutral: literal `command`/`extra_args`, `harness_kind`, optional whole-argument `{prompt}` in `initial_prompt_args`, optional `{hook_path}` in `hook_args`, and replacement `resume_args` with one whole `{session_id}`. OMP supports an optional per-launch public-API hook; no mandatory extension/model flag, global installs/settings, shell interpolation, fabricated conversation ID or automatic `--continue`. Resolved settings stay with launch intent. Launch acknowledgement, physical readiness, credential activation and first model response are distinct; <10s launch/<5s communication remain desired targets until measured. [Owner](crates/cockpit-core/src/orchestration/dispatch.rs). Rationale: Fast local launch is not proof of model readiness.

- Ordinary editing, shell, plans and affected checks continue offline without a blanket local-tool gate. Cockpit has no harness-native child registry, lifecycle controls or SDK retirement path; harness-internal children do not acquire Cockpit task authority. Private role credentials remain same-UID accident prevention, not an OS sandbox. [Owner](crates/cockpit-core/src/orchestration/credentials.rs). Rationale: Semantic authority must not disable legitimate local work.

- Core tasks, schedules, replacement, credentials, messaging and cleanup are harness-neutral. Herdr-supported agent interactions, credential CLI and optional harness hooks are allowed adapters; OMP's thin hook is the first adapter, not exclusive agent support. No OMP auth export, session file or native detector is a product-authority prerequisite. Other configured harnesses retain literal argv launch, optional actual conversation and extension-free coordination. [Owner](crates/cockpit-protocol/src/projects.rs). Rationale: A local workbench must not equate orchestration with one harness.

- Durable operations are keyed by principal plus operation UUID and retain the exact payload, original source/revision fences and bounded file bytes before delivery. Authentication and current assignment/capability admission precede exposing a committed replay as an authorized mutation; historical receipts cannot restore revoked authority. Changed payload under the same principal/UUID conflicts. Different authorized principals may independently use the same UUID, but a foreign principal never receives another principal's original receipt. Pending means locally retained, not delivered or committed remotely. Durable effect intent and exact receipts support reconciliation, never blindly repeating an unknown external effect. [Owner](crates/cockpit-core/src/orchestration/store.rs). Rationale: Recover uncertainty without creating a second writer or claiming exactly-once effects.

- Working TaskScopeUpdate fences task and document revisions and recovers canonical Markdown plus one same-worker instruction as a durable intent. The instruction points to canonical scope rather than copying its description. The current canonical task revision may differ from the immutable launch-time task revision; SourceOutput uses the current revision. Conflicts retain submitted drafts and external edits. [Owner](crates/cockpit-core/src/orchestration/scope_intents.rs). Rationale: Launch provenance cannot freeze or silently replace current task scope.

- Briefs/instructions/answers/reports are untrusted durable data. Credential-scoped CLI `inbox next` waits/pulls and completes capture bookkeeping internally, without an extra ACK model turn; capture is not an Answer, resumed work, unassignment or acceptance. The optional per-launch OMP hook uses supported session metadata and `sendUserMessage`, coalesces delivery and never changes settings, gates tools, types into terminals or overwrites drafts. Extension-free CLI delivery remains complete. Default-off counts-only prompt hints use separately identity-checked supported `agent.prompt`; busy/unready targets defer and unknown submission is not blindly replayed. [Owner](crates/cockpit-core/src/orchestration/messages/inbox.rs). Rationale: Efficient delivery must preserve authority and uncertainty.

- Effective materialized hook launches alone mark `COCKPIT_INBOX_HOOK=1` to designate inbox consumer ownership, not grant authority. Hook-active bootstrap/agents avoid duplicate manual long waits/capture; disabled hooks retain credential CLI waiting. OMP busy meaningful delivery uses public safe-boundary `deliverAs: "steer"` rather than whole-turn followUp deferral, without aborting tools, killing writers or touching terminal drafts. Queue/capture does not prove model processing or first-response latency. [Owner](integrations/omp-hook/cockpit-hook.ts). Rationale: Prompt coordination must be responsive without duplicate consumers or unsafe interruption.

- An Answer links to the destination run's exact current NeedsInput message ID; unrelated instructions or reports cannot replace it. Exact sender replay preserves ID/payload/link; changed payload conflicts. Optional Initialized, latest quiet Progress, NeedsInput and Result retain run/assignment and actual supplied conversation provenance. Worker questions go to the liaison, and human decisions occur in the liaison conversation, with only a quiet root-wait hint in UI. [Owner](crates/cockpit-core/src/orchestration/messages/report.rs). Rationale: Durable delivery does not prove a model answered or authorize control.

- After receiving the actual human answer in its conversation, only the root credential may `run answer --in-reply-to` its exact current unresolved root NeedsInput. If Cockpit never observes the highest Space ID close, then Herdr restarts and reuses that ID before the next observation, the exposed identity cannot distinguish the replacement; no name/path fingerprints or reassociation conceal this upstream limit. [Owner](crates/cockpit-core/src/space_tags.rs). Rationale: Retain restart continuity without inventing a durable Herdr identity.

- Sidebar arrows/Home-End/left-right/Menu move DOM focus only; Enter/Space/click requests Herdr focus and selection follows ACK. Pending target uses neutral marker, and aria-disabled during mutation preserves keyboard focus. [Owner](src/app/sidebar/useRovingList.ts). Rationale: Navigation intent is not acknowledged selection.

- Below header, Spaces/Agents each reserve one-third of area and share remaining third by entry counts, scrolling independently; no entries splits equally. [Owner](src/app/sidebar/Sidebar.tsx). Rationale: Both lists need usable space under varying counts.

## Engineering and delivery boundaries

- Keep core Rust rules independent of Tauri/HTTP/WebSocket/socket framing; hosts compose narrow Herdr/provider/OS-vault traits. Share typed client requests/streams with startup adapter selection and validated response identity; stable typed error codes/useful messages stay at failure owner. - Serve shared frontend/versioned HTTP-WebSocket API from explicit foreground loopback origin only, with native access restricted by Tauri capabilities; browser has no separate remote authentication. [Owner](crates/cockpit-host/src/server.rs). Rationale: The trusted workstation boundary is not a remote service.

- Keep native dragDropEnabled false so shared HTML dragover/drop drives tab sorting; do not consume native file-drop events. [Owner](src-tauri/tauri.conf.json). Rationale: Native interception can swallow frontend tab drops.

Rationale: Less rendered work is not causal performance improvement.

Serialize per skill and revalidate held identity, retaining final same-UID writer race and independent outcomes; inspect saved results on exit 20 rather than blind replacement retry. [Owner](crates/cockpit-host/src/bin/cockpit/skills.rs). Rationale: Skill installation must preserve unrelated user files.
