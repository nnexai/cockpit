# Cockpit decisions in force

This file records current product and engineering rules, not the implementation diary. Herdr and the repository are sources of truth for their respective state; UI details may evolve without changing those ownership boundaries.

## Herdr authority & compatibility

- Herdr owns live sessions, Spaces/workspaces, tabs, real terminal existence and membership, PTYs, processes, focus identity, and agent state. Cockpit does not keep a competing live registry. Cockpit-owned companion associations are evidence about Cockpit's files, not another workspace authority.
- Use the supported Herdr socket/schema surface for persistent session state and terminal streams. Validate protocol, schema, and every required method before advertising compatibility; fail closed on mismatch. Display-version text is diagnostic and is not an exact patch-version allowlist. The adapter currently requires protocol 22, schema 1, and its required-method set.
- **Client-shell capability.** Native and browser hosts share the same session metadata, resource mutation and direct terminal contracts through the core/Herdr adapter. Custom command and popup discovery uses Herdr 0.9.2's generation-1 client-shell surface, with identity and mandatory codec checks; `shell_unsupported` is a capability error, not permission to guess bindings or downgrade. Disconnected/timeout/malformed/identity failures stay explicit; retired commands and popup targets reject invocation/attach with `command_not_available` / `popup_not_open`.
- Build client state from an authoritative snapshot and ordered events. On gaps, identity changes, reconnect, or stale state, resnapshot and rebind rather than guessing. A mutation acknowledgement is not itself fresh focus or control authority; that comes from the ordered Herdr state.
- **Tab placement.** Cockpit owns each tab's split tree of real terminals and local Files/Review/Browser viewer leaves. Layouts live only in memory for the run, keyed by session, server instance and tab id; they are never persisted. Herdr rectangles, zoom and positioning hints are ignored. Dragging, divider resize, swap and zoom are local actions and send no `pane_resize`, `pane_swap` or `pane_zoom`. Terminal fitting still updates the attached PTY's grid.
- First load uses a balanced grid ordered by stable pane id. Externally created terminals insert at the full-height right edge, with share `1 / (existing leaves + 1)` including leaves hidden by zoom. Cockpit-created terminals are placed beside the acted-on leaf using Herdr's validated creation receipt, never inferred from focus or a snapshot difference.
- **Focus identity.** A changed Herdr focus triple (Space, tab, real pane) is followed unless it is the echo of a Cockpit request; zoom is restored if it hides that terminal. Repeated unchanged focus never steals selection from a viewer. Selecting a viewer sends no Herdr focus request. Layout selection, Herdr focus, attachment/input ownership and DOM focus are four separate states.
- **Membership.** Confirmed loss of a tab or its last real terminal, by close or move, retires its layout, releases Files/Review contexts and stops its Browser session. Durable comments and browser work remain. Loading, stale or disconnected state is never membership loss.
- Agents-list ordering is client presentation, as in the Herdr TUI: Herdr's API returns agents in workspace order, and the TUI applies its `priority` sort itself. Cockpit always uses that priority order (blocked, done, working, idle, unknown; newest state change first) and does not read Herdr's `agent_panel_sort` setting or plugin agent views.

## Terminal attachment & input

- Herdr owns the PTY and terminal model; xterm.js renders and captures input. Every terminal painted in the active tab attaches with `mode: control` at Cockpit's fitted grid; there is no observe attachment or downgrade. Input additionally requires DOM focus, Herdr-confirmed focus and owned control. Stable terminal frames and their sequence are authoritative; do not reset xterm on a full repaint.
- A tab switch attaches the target tab's painted terminals at Cockpit's grid before asking Herdr to focus it (up to 300 ms, released by the focused pane's first frame), and the old tab's terminals stay attached until the swap is painted. With no painted terminal there is no gate. Herdr resizes a pane on control attach and restores the TUI's size on disconnect; attachment eligibility is fresh membership in an existing tab, not Herdr geometry.
- Terminals hidden by zoom, an inactive tab or the Library detach without stopping Herdr processes or losing scrollback. Files/Review view state stays in the layout store; hidden Browser views release capture resources without closing the managed session.
- After a tab switch, DOM keyboard focus moves into the incoming selected terminal only once it is painted and Herdr has confirmed control; the terminal attaches hidden earlier, and a hidden element cannot take focus. Closing the Library by any route lets the selected terminal take focus after reattachment, except when restoring an explicit connected sidebar invoker.
- Keep ordinary terminal bytes on the attachment input path. Route wheel/page scrolling through the attachment's scroll operation and application mouse through the attachment's structured, cell-coordinate mouse operation when Herdr signals capture demand. Do not substitute raw SGR injection for structured mouse. Control intent, confirmed Herdr focus, attachment state, and process lifetime remain distinct.
- Attach, resync, and retry failures must leave the Herdr resource intact and visible with its status and recovery action. A request with an uncertain mutating outcome is not safe to repeat automatically; recover by inspecting authoritative state.
- When investigating mouse or terminal input, name the exact input path tested: **physical attach, xterm wheel, structured AttachMouse, or CLI-injected SGR**. State only the acceptance dimension observed for that path; evidence for one path does not establish another.
- **Server popup.** Render Herdr's singleton popup terminal as a centered floating surface above the existing split tree, respecting server size hints without inserting or reflowing leaves. Keep underlying painted attachments, make the underlay inert and gate ordinary pane input, including while a popup invocation is pending. Popup input uses the ordinary direct terminal transport with an explicitly validated popup target. Esc, Enter, Tab and prefix chords belong to its program; no local forced close or workbench shortcut runs behind it.
- **Popup lifetime and focus.** Only fresh authoritative popup metadata closes or replaces the popup. A stale/disconnected popup remains visible with input disabled, status and retry. On server closure let the eligible selected terminal regain keyboard focus; delayed opener restoration must not steal it. If no selected pane has regained focus, restore the available opener, else selected-tab chrome. Do not mutate Herdr focus merely to open or dismiss a popup.
- **Active shell geometry.** Accept the existing Herdr active 120×40 client-shell surface subscription required for command/popup metadata. It can resize unattached panes and a concurrent Herdr TUI; it is not a geometry-neutral observer. Direct control attachments protect painted Cockpit panes' fitted PTY sizes, and this subscription does not change Cockpit's split layout.

## Keyboard

- **Keyboard scheme.** Cockpit-wide shortcuts remain `Ctrl+B` prefix sequences on every platform. A key Herdr binds by default keeps its action meaning in Cockpit or stays unbound; Cockpit-only actions use keys Herdr leaves free. Deliberate difference: Cockpit does not implement Herdr-only built-in prefix actions (`s`, `q`, `e`, `[`, `o`, `Shift+G`, `Shift+R`). Pane cycling is `Ctrl+B Tab` / `Ctrl+B Shift+Tab` in local visual order. The static registry (`src/app/input/shortcuts.ts`) drives Cockpit Commands, tooltips and the generated keyboard-doc section; runtime custom bindings are a separate server-owned projection, not fake static entries.
- **Advertised custom commands.** Discover generic shell, pane, popup and plugin-action commands, their direct/prefix aliases and configured Herdr prefix chords from the identity-checked live server projection. Reload replaces bindings rather than retaining retired aliases. Invoke opaque advertised IDs with confirmed Herdr focus context, revalidating current command and membership; unknown actions stay unavailable. This is not a launcher-specific or plugin-private API integration.
- **Collision precedence.** Direct advertised chords precede local viewer shortcuts outside editors and local dialogs. A configured Herdr prefix arms advertised prefix bindings; Cockpit keeps `Ctrl+B` independently. When Herdr also configures `Ctrl+B`, custom prefix bindings win collisions with Cockpit actions; a different Herdr prefix does not redirect Cockpit-only actions. Commands/tooltips omit shadowed local shortcut labels. Literal-prefix passthrough is reserved before custom prefix lookup: `Ctrl+B Ctrl+B` sends a literal `Ctrl+B`, and a Herdr-armed prefix followed by a configured Herdr prefix passes the chord through.
- **Terminal claim set.** Except for advertised custom direct/prefix bindings and configured Herdr prefixes, a terminal or inline browser surface retains Cockpit's narrow claim set: `Ctrl+B` plus the next key, clipboard chords (`Ctrl+Shift+C/V`; `Cmd+C/V` on macOS) and `Shift+Enter`. Unbound plain `Tab`, `Shift+Tab`, Alt-, function- and Ctrl-chords reach the program. While a popup is open the workbench router yields entirely to its terminal.
- **Browser surface.** Prefixes and advertised bindings are recognized from the inline browser surface, not from its URL field or note editor; literal double-prefix passthrough avoids the keyboard trap.
- **Pane commands over the Library.** A pane-scoped prefix command closes the Library first, then acts on the selected pane.
- **Local pane commands.** Commands act on the selected leaf of any kind: splitting creates real terminals, focus/cycle/swap use Cockpit placement, and zoom is local. Viewers cannot move between tabs or Spaces. Esc restores zoom only on layout chrome; in a terminal, browser or viewer it belongs to that surface. Esc cancels an active drag.
- **Library close focus.** Closing the Library by its toggle key, toolbar button, Close button or Esc lets the selected terminal regain DOM keyboard focus after reattachment. Preserve an explicit connected sidebar invoker instead. A graphical originating pane regains focus if it is still selected. This changes DOM focus only, not Herdr focus.

## Workspace & filesystem ownership

- Setup opens a chosen directory by path or creates a worktree through Herdr's worktree API. Opening a checkout does not make it Cockpit-owned; an opened directory remains borrowed. Cockpit does not clone repositories or use display labels as filesystem authority.
- Cockpit owns its companion context and operation records. A companion manifest records association/provenance and must be checked against fresh Herdr evidence; it is not a live workspace registry. Publish companions without replacing an existing destination.
- Destructive teardown requires explicit ownership plus the exact creation receipt and fresh checks of linked-worktree, endpoint, and clean status. Missing or ambiguous evidence never grants deletion authority. Preserve operation receipts across closed dialogs and uncertain responses; reconcile the recorded operation instead of dispatching setup twice.
- Keep filesystem reads bounded, rooted, identity-checked, and no-follow where applicable. Revalidate roots/source identity before mutations or returning comments: a path, label, or prior snapshot alone is not authorization.
- Setup is plan-driven and path-only for Open. The plan is tied to its input; stale plans require a fresh user start. Provider links may identify/import artifacts but do not select or clone a repository on the user's behalf.

## Context & Review

- Files, Review and Browser are Cockpit-owned tab-local viewers, at most one of each kind per tab. Opening an existing viewer focuses it; Files/Review switch to the requested source and retain per-source view state. Viewers never launch addon TUIs and have no terminal/renderer toggle. Existing addon panes remain ordinary Herdr terminals.
- Files/Review use a core-issued viewer context and source binding opened from a real same-tab terminal. Authorization pins the selected source root, cwd, endpoint, tab and Space, then rechecks fresh tab membership, binding and filesystem identity on each request. The source terminal may subsequently close or change cwd without retargeting the viewer; unrelated roots never become authorized through it.
- Context and Files use Cockpit's bounded filesystem model. Companion-specific operations require a verified companion; ordinary file browsing and Review can be rooted in a freshly verified local checkout without granting companion write authority. Unsafe, stale, oversized, or unsupported sources fail closed.
- Review is Cockpit's read-only local Git view plus shared comment capture. Comments retain immutable source identity/line anchors, and source state is re-evaluated before a successful save or delivery. Stale or uncertain deliveries retain recoverable drafts/receipts and never submit Enter to an agent.
- Comment ownership is tagged `viewer` or `legacy_pane`; source identity and authorization remain mandatory for save, reattachment and delivery. Comment batches and paste receipts are run-local: view closure does not delete them, but the next owning-runtime startup clears the pane comment store.
- File-picker indexes are hints only: server authorization is checked on each request and each fresh open re-enumerates the root. Git indexes exclude ignored files; other roots use a bounded no-follow walk. Persisted XDG-cache data contains paths and metadata only, never file bodies or authorization evidence; `COCKPIT_CACHE_ROOT` overrides the configured `cache_root`.
- The picker list is eventually consistent without user action: the viewer warms the client list in the background on root open and window focus (30 s throttle), an open picker shows the cached list at once, replaces it with the fresh one, retries failures with backoff, and quietly revalidates every 8 s while indexing stays under 2 s. A slow index only changes the status text; it is never aborted or left as a dead end.
- Review snapshot reuse requires matching current revision tokens, repository/source/comparison identity, and resolved branch merge base, and is skipped for any snapshot that contains untracked files (their tokens are metadata only, so a same-size rewrite that keeps its mtime would look unchanged). The versioned viewer-bound snapshot must still load before an in-memory reuse hit is returned. Recognized pre-viewer cache filenames are pruned without deserializing their obsolete payloads; malformed current-format cache data remains an error. Git digest commands stream stdout under the normal process timeout.
- The repository catalog scan may be served from a bounded in-memory cache on read-only Context/Files/Review paths (fresh 30 s, stale up to 5 min with a background refill, invalidated on any Cockpit store mutation). Per-directory checkout discovery is never cached: it decides which checkout a runtime path belongs to, so it always runs on the original path (no symbolic links, current Git boundary). Setup, plan, resume and teardown checks never use the cache.

- The global Context Library is a Cockpit-owned view below the tab strip, not a Herdr pane, tab, or synthetic resource.
- With no session loaded, the view is Library-only: there is no target Space or pane authority, and Space actions are absent. Opening or closing the view never asserts Herdr focus, pane selection, or process authority, and never changes a tab's local layout. Membership and focus reconciliation continue while it is open.
- While the Library view is shown, visible pane renderers and live output subscriptions are unmounted; closing it lets the selected tab's panes attach/resynchronize. Do not keep hidden terminal renderers or subscriptions mounted for the Library.
- **D13 focus policy:** on open, move DOM focus into the selected/first Library tree row. On close, restore an explicit connected sidebar invoker; otherwise let the eligible selected terminal regain keyboard focus after reattachment. Restore a graphical originating pane when it is still selected, or safe workbench chrome when no eligible pane can take focus. Closing never sends a Herdr focus request.
- Pasting a prepared comment targets an explicitly selected eligible agent in the same actual tab. Preparation and send validate current payload/source; preview is optional, and sending does not submit the terminal command. Keep pending, rejected, and unknown outcomes distinct to avoid accidental duplicates.

## Inline browser

- Browser is a Cockpit-owned tab-local viewer with one independent managed session per Herdr tab, not a Space sidecar or Herdr pane. Tab switch, zoom and Library hide its view. Closing the viewer, losing the tab's last terminal or shutting down its owning runtime stops the session and removes only its proven Cockpit-owned profile and launch artifacts. Cookies, logins and site storage are disposable; cleanup failures remain visible and retryable.
- Creating/reopening a Browser leaf uses `OpenFresh`: surviving sessions are stopped and cleaned, never adopted, and the new session starts at `[browser] default_url` or `COCKPIT_BROWSER_DEFAULT_URL` (default `about:blank`, validated at configuration load). CLI `Open` and an existing leaf's Reconnect retain their attach/new-page semantics.
- **Ephemeral pane state.** Browser sessions/profiles, annotations, drafts, pending captures, feedback and delivery receipts, Files/Review comment batches and paste receipts, and Review scratch caches last for one owning-runtime run. Only the process that acquires the exclusive browser owner lock resets these stores, before publishing its socket or constructing dependent services; observers never reset an active owner's state.
- **Startup reset.** Stop proven leftover managed sessions first, then clear `browser/` except `owner.lock` and `owner.sock`, plus `comments/` and `review/`. Preserve the lock inode; use no-follow, same-device deletion limited to these pane-state roots. If shutdown cannot be confirmed, fail startup without wiping browser state. Never touch Library content, credentials, configuration, project operations or real Herdr sessions/terminals.
- Closing/reopening fresh, tab/final-terminal retirement and owner shutdown discard the outgoing browser association's work as well as its profile. Saved-tab/archive recovery APIs, reviewed legacy-file panels and saved-work close guards are removed. Current-run cleanup failures stay inline and retryable. Browser cleanup requires confirmed shutdown, derived paths and identity checks; the CLI targets `--tab` or `--current`, never detached `--legacy` work.
- Unsent notes and annotations belong to the page/document they were created on. Navigation retires that page's drafts; drafts for other open tabs and drafts referenced by a prepared capture remain only within the current run and live association. Preserve current-run delivery reconciliation; unknown outcomes are not automatically replayed.
- Preserve target, document, viewport, and ownership checks for input and captures. A capture must refer to the pinned frame and immutable submitted image; do not turn incomplete or lower-density live imagery into saved-frame evidence.
- **Accepted requirement, implementation/acceptance not verified:** attempt sharp browser images when safe and affordable, but allow lower resolution to preserve responsiveness during animation, hover, or scrolling; pursue affordable quality again as activity eases. Do not freeze older sharp imagery, poll continuously, or weaken frame/target/lease checks. Measure Chromium capture separately from Linux WebKit display/input. See [Live browser image quality](planning/stability-and-gitlab-2026-09-20/ACCEPTANCE.md#live-browser-image-quality).

## Providers & setup

- Provider adapters expose supported capabilities and explicit unsupported-operation errors; Cockpit reads/imports and validates provider data, while remote writes remain with provider CLIs or the user's usual tools. Provider metadata may inform a plan but does not override local repository choice or Herdr ownership.
- Current setup supports configured local repositories, path-only Open, Herdr worktree creation, and configured artifact lookup/import including Jira work items. Jira lookup uses the configured `jira` CLI/site, and string (wiki-markup) bodies from self-hosted Jira are converted to Markdown while ADF bodies keep their own path; a Jira URL or ticket key never chooses or clones a repository. Imported artifacts are bounded and validated before setup; setup does not follow references (that is the Library `reference_depth`).
- Prefer explicit, bounded hydration and canonical snapshots with source identity/revision where available. Freshness checks use provider metadata when available and canonical content otherwise. A failed optional import should not erase successful assets or silently become a successful import. Following references is one explicit `reference_depth` (see the reference-depth bullet under Library decisions), never a per-provider boolean.
- Generated issue-like Library documents use frontmatter for known provider facts and a title/summary followed by optional Description and chronologically ordered Comments sections. Comments are Markdown cards with stable local timestamps, provider permalinks, edited timestamps only when changed, and provider headings demoted beneath document/card headings; partial lists retain shown/total counts.
- Configuration comes from supported file, environment, and invocation options. Secrets never enter context snapshots, generated environment values or configuration files; see the Provider credentials rule.
- Provider imports are authorized by the selected configured provider instance and the artifact's validated canonical identity/URL, not by a checkout's Git origin.
- **Provider credentials.** Cockpit stores one pasted API token or PAT per configured provider id and instance (`base_url`) in the OS vault (Linux Secret Service; macOS Keychain is compiled but unverified), keyed `cockpit` / `<provider id> <instance>`; a token counts only for that exact instance, so changing `base_url` never re-targets it. Only Jira and Confluence support it (`Bearer` or `Basic` with a username); glab, gh and tea report `unsupported` (tea always passes `--login`, which overrides an env login). The client boundary is write-only: set, clear and a presence/kind status list, with no read path, and no secret, username or vault detail reaches the frontend, logs, errors, argv, Library files or configuration. A stored token reaches only that provider CLI's child-process environment, pinned to the configured site (`JIRA_SERVER`, `CONFLUENCE_DOMAIN`). Cockpit's own HTTP sends `Authorization` only to the configured origin (scheme, host, port), never after an https to http downgrade, and follows cross-origin redirects (Cloud media) without credentials. With no token stored, or the vault unavailable, CLI spawns keep the CLI's own login and the failure is not cached; native HTTP has no CLI to fall back to and fails with `source_credential_required` or `credential_vault_unavailable`. Vault calls time out at 20 s; the per-process cache means changes made in Seahorse/KWallet are seen after a restart. Passkeys/WebAuthn and OAuth sessions are not storable secrets; only pasted tokens are. Verified live against Jira Cloud (Basic, jira-cli) and Confluence Cloud (env mode) with a private gnome-keyring; Jira Data Center Bearer and macOS Keychain are fixture/compile-only.
- The Library is the durable global source: add and refresh save there first. A companion copy changes only through an explicit operation targeting that Space; Library refresh never automatically fans out or synchronizes companion copies. S2 exposes explicit per-Space add/list/retry/dismiss actions. S3 adds selected-item/All update, confirmed compare-and-swap replacement of edited copies, and confirmed per-Space removal; removals and source disappearance keep other Space copies unchanged.
- Local folders are typed-path copies into the Library, never live links. Capture uses canonical no-follow roots, rejects all overlaps with Cockpit-owned roots, excludes and counts unsafe/special files, and reports configured file/byte limits as sorted partial copies. Re-copy is explicit and preserves edited Library bytes behind CAS. The old repository-snapshot action/transports are removed; existing `repos/` entries stay `Not linked`, and `<state_root>/sources` remains inert. Multi-file Space copies mirror Library-relative paths with one manifest/hash record per file; update/removal preserve edited bytes unless exact listed path hashes are confirmed.
- The Library disk layout is readable without Cockpit: real nested directories mirror each source's hierarchy (`<provider>/<host>/…/<leaf>/<Title>.md`, attachments in `_files/`), titles are kept except unsafe characters, and all machine state stays in `.cockpit/`. Moves are directory renames, never copies. Space companions mirror Library-relative paths. There is no migration from the flat layout (index schema 1); such Libraries are wiped and re-added. Index schema 2 (nested layout) is upgraded to schema 3 in place by a raw-JSON upgrader that rewrites journal intents first and the index with its schema flip last, so a rerun is idempotent. The upgrade is one-way: an older binary reports schema 3 as corrupt. Wipe-and-re-add was rejected for it because live Libraries hold Confluence follows.
- Markdown links resolve only inside the current Library or Space root; links to Library source URLs open the Library item or its Space copy.
- **Confluence read contract:** page imports use an explicit `confluence` CLI read allowlist with read-only mode and analytics disabled. A page URL/ID is accepted only under its selected, validated configured instance; ambiguous authority fails closed. Page add/refresh captures attachment metadata only. Explicit per-page download or a follow's opt-in downloads binaries through the allowlisted CLI into private staging with exact predicted matches, no-follow regular single-link checks, safe stored names, per-file limits, periodically monitored aggregate staging budgets (not hard filesystem quotas), and atomic publication; no download happens by default. Confirmed Library replacement re-downloads an edited binary only after matching its exact current hash, and opted-in follow refresh retries failed downloads. Only PNG/JPEG are active media. PDF has no renderer; SVG/HTML are not executed. Space copies keep the page and `attachments/` in one relative layout and preserve/report edited files during update/removal. **Jira attachments are listed, and downloadable with a stored token.** `jira issue view --raw` reports `fields.attachment[]`, which the Jira provider maps to `SourceAttachment` metadata (`jira_attachments.rs`). jira-cli 1.7.0 offers no attachment download, so Cockpit's own same-site HTTP client (`jira_attachments/download.rs`) fetches the bytes with the Cockpit-stored token (`/rest/api/2/attachment/{id}`, whose `content` URL must be same-origin; the stored `source_url` is never trusted), at most three manually followed redirects, and the same staging, budget and publish rules as Confluence. Without a stored token, a per-item download or add with downloads fails with `source_credential_required` (`credential_vault_unavailable` when the vault fails) and the UI offers the token dialog; a follow's opt-in saves issues and reports that note per row. Download is covered by fake-server tests only: no live Jira attachment has been downloaded and Data Center is fixture-only.

- A Confluence space follow is an explicit snapshot of every readable page across the space, including separate top-level trees; Cloud folder ancestors are hierarchy nodes, not page documents. Refresh is user-triggered; page lookups are concurrent and new or changed pages are fetched with a bound of eight in flight, then published in deterministic parent-first order with each page retained as its own crash-safe Library commit. Only complete enumeration plus per-page confirmation may mark pages removed at source. Partial, failed, or cancelled enumeration does not infer absence or mark pages removed. Excluding a followed page persists until the entire space is followed again; stopping a follow keeps its pages as ordinary Library items.
- Space follow state is per target Space and follow: one aggregate row represents a follow, and an explicit selected-follow update writes only its new or changed pages in that Space. It must not fan out to other Spaces or other follows. Preserve known page identities so a page copy deliberately removed from a Space is not re-added. Skip edited copies by default; replacement requires confirmation bound to exact current file hashes.
- **Reference-counted Library items.** Every item carries a sorted, deduplicated `refs` set (`Manual`, `Follow{follow_id}`, `Space{companion_root_id}`) that replaces the old single `follow_id`; a pin is just a `Manual` ref ("Keep in Library"). Refs change only through `mutate_index` under the exclusive lock (plus the birth ref of a new item); publish, update and journal replay keep the index's current refs and purge time, so concurrent follows cannot lose each other's membership. An additive `#[serde(default)] refs` was rejected because an empty default means "unreferenced" and would tombstone every migrated item. An item with no refs gets `purge_after` and is deleted by the sweep at the end of every add/refresh once due, unless it is leased or has local Library edits. A live follow drop waits 14 days (`TOMBSTONE_GRACE_MS`, not configurable); explicit removal (Remove follow with items, removing the last Space copy) is due at once. Consequence (Q5): a page that was added manually and later covered by a followed Confluence space survives removing that space because it holds `Manual`; migrated data is unaffected because v2 members map to `Follow` only.
- **Jira query follows.** A follow is a normalized JQL string (a bare project key means `project = KEY`) in mode `live` or `accumulate`; its id is a hash of provider, instance and JQL and keeps the `follow:` prefix. Each issue is one item, keyed by provider, instance, `issue` and key, shared across follows, at the unchanged `jira/<host>/<PROJ>/<KEY>/<Title>.md` (a flat `<KEY>.md` would break the store's document-inside-item-directory invariant). Issue reads go through jira-cli 1.7.0 only, allowlisted to `issue view KEY --raw` and `issue list --jql … --plain` with fixed columns and a unit-separator delimiter; every query is sent as `project IS NOT EMPTY AND (<jql>)` to defeat the CLI's default-project injection. Listing is windowed by `updated DESC`, 100 per call, never by offset (broken on Cloud), and capped by `library_space_pages`. Refresh compares the listed `updated` with the one stored at the last fetch and fetches content only for changed, removed, failed or unknown items; item metadata (`issue`) never enters `content_revision`. A live follow drops members only after a complete, uncancelled, non-empty listing; a failed, truncated, cancelled or empty listing keeps everyone. `accumulate` never drops, probes from a watermark derived from members and key-checks the members the probe skipped, and defaults for queries with relative dates. Any incomplete accumulate run leaves the follow partial so the next run lists in full. `Stop following` keeps items (exclusive members become `Manual`); `Remove query and its items` deletes only exclusive members and is refused if one has local edits. A custom jira-cli `timezone` converts the plain `updated` values, which could shift window bounds above 100 results; the supported setup leaves it unset. Attachment bytes are fetched by Cockpit's same-site HTTP client with a stored Cockpit token, per item or by a follow's opt-in.
- **Reference depth.** One `reference_depth` (API 0 to 5, `library_reference_depth_invalid` otherwise; UI `Follow references`: Off/1/2/3) replaces the boolean `hydrate_references` and the same-repository forge crawl, with no alias. Defaults: single Jira issue 1; forge issue/PR, new Jira query and any stored item or follow without the field 0 (additive `serde(default)`, no schema bump). Confluence page adds and space follows reject depth above 0; folders ignore it. References are Jira structured `parent`/`subtasks`/`links` frontmatter fields (chosen over a new `SourceAsset` field, which would touch every provider literal) plus Jira keys and URLs in description and comments and URLs in other bodies. A URL is followed only when it resolves under a configured provider instance (Jira, Confluence pages, GitHub/GitLab/Gitea issues and PRs) with the direct-import authority checks; reached items expand at the same depth by the same rules regardless of provider, and Confluence spaces, unsupported and unconfigured URLs stay links. Traversal (`SourceService::collect_related`, fetch-only) is breadth-first, deduplicated by canonical Library identity so cycles collapse, eight fetches in flight, at most 64 references per asset, with internal non-configurable caps: single import 32 related items/8 MiB/60 s, query follow 100/16 MiB/180 s. Seeds are saved before traversal; a failure, cap or cancel is a Partial row, never touches seeds and never authorizes a drop. Storage keeps one `included_by` reason per holder (shallowest route, relation, step); Details renders each distinct reason once (the UI deduplicates identical rendered reasons). Single import: depth persists on the seed and each explicit refresh re-traverses; related items get `Manual` plus a seed-held reason, so they survive seed removal and a complete refresh only strips the reason. Rejected: a new seed-held ref kind (the set only grows, like accumulate, and the boring model matches the old linked items). Query follow: related items get `Follow{F}` plus a follow-held reason; an item the query lists is a seed and drops the reason; a live follow drops unreached related items only after a complete related pass and complete listing, accumulate never does; unchanged seeds are traversed from stored `references`, and old seeds without them are refetched once. Space independence holds: refresh never fans out, Jira follows stay out of Spaces, a single add targeting a Space copies what that add saved. Live-verified only for a Jira and Confluence graph (SCRUM-7 to SCRUM-9 with a cycle: depth 0/1/2 saved 1/3/4 items, JQL depth-1 follow and refresh correct); forge URL expansion is fixture/contract verified, not live.
- **Jira follows are out of scope for Spaces.** Add to Space and selected-follow updates reject a Jira follow id with `source_capability_unavailable` and the Add dialog hides the Space destination for a query. The Space follow layer is page-worded and needs its own design for live drops. Individual Jira items can still be copied into a Space, which adds a `Space` ref.
- **Library tree grouping and nesting.** The tree is provider instance → container → item, and every level is keyed by provider id and instance, never by host: Jira and Confluence on one Atlassian site are separate instances. A Jira query follow is a container under its own provider only, and an item another provider pulled in through a followed reference (a Confluence page linked from an issue) sits in its own provider's container, not under the query. A follow row shows its query (or space) as its name, ellipsised only on overflow with the full text as tooltip, and puts `Following` and its count on a second line. A Jira subtask nests under its parent issue when the parent is in the same container; otherwise it stays a top-level row. The parent is the stored `parent` reference of the issue's document, projected into `parent_item_id` by the listing only: the stored `parent_item_id` of a Jira issue stays empty because it decides the on-disk layout. A copy saved before references were captured has no parent until it is next fetched. Siblings keep the issue order (newest key first).
- **Library tree keyboard.** The tree has one tab stop (the row that last held focus, else the selected row, else the first). ↑ ↓ Home End move focus; → expands a group or enters its first child; ← collapses or moves to the parent; Enter opens an item and toggles a group; Space is the row's own click; Shift+F10 and the Menu key open the row menu. A navigation key pressed while focus is on `<body>` (a button that disabled itself, a closed menu) takes the tab stop back, so a refresh or dialog never leaves the arrow keys dead.

## Subscription limits

- Quotas are read-only CLI-owned data: Codex/Claude via OMP and Copilot AI credits via GitHub CLI. Cockpit does not acquire/store credentials, run sign-in, switch accounts, redeem credits, or invalidate OMP's cache. CLI authentication may have its own refresh side effects.
- Copilot is credit-based only when both token-billing flags and explicit credit quantities are present. Unsupported/legacy premium-request data must remain unsupported, never be converted into AI credits. The internal GitHub account endpoint is a compatibility risk.
- Native/browser runtimes sharing a configured cache root share source schedules, a cross-process lock, and persisted pre-command leases. Collection is demand-driven, at most once per five minutes per source; source failure backoff is 5/10/20/40/60 minutes. Cache failure never permits a process-local collection fallback.
- Persist and transmit only allowlisted quota data and anonymous accounts. Preserve source observation times; failed or over-15-minute-old values are visibly stale, and over-24-hour-old values are unavailable. Missing windows, unknown quantities, zero balances, and unlimited entitlements remain distinct.
- Use the existing 28 px work-area strip, not another footer. Mouse hover previews read-only details without taking keyboard focus; leaving the strip/popup or pressing Escape closes the preview. Click, Tab/Enter, or Commands pins details open, with normal opener restoration on Escape; no dedicated chord. Remaining-quota meters are amber above 80% used and red above 95% used (strict thresholds), independently of provider-reported levels; stale hatching remains muted. Hidden clients pause reads, and active-agent state does not shorten the collection cadence.

## Sidebar presentation

- **E1.** The sidebar keeps Herdr's hierarchy, order, urgent-state rollup, lowercase section labels, two-line agent rows, branch line and trailing repository chevron. It intentionally differs in these ways only: (a) worktree children show a shortened name (Herdr label or branch without a leading `worktree/`, `worktree-` or repository segment) with the full name and checkout path in the tooltip; (b) the second line of an agent row is `State · agent` instead of the agent name alone; (c) status marks are drawn as SVG badges, a state-tinted disc with one of five distinct shapes, instead of text glyphs.
- **E2.** Sidebar keyboard navigation (arrows, Home/End, ←/→, Menu key) moves DOM focus only. A Herdr focus request is sent only by Enter/Space or a click, and selection chrome follows Herdr's acknowledgement. A pending target shows a neutral marker, not the selection accent. Rows use `aria-disabled` while a mutation is in flight so keyboard focus is kept.

## Deferred scope

- Automatic OMP setup/launch; Cockpit-driven provider sign-in flows (OAuth, passkeys) and glab/gh/tea token injection; remote browser access and multi-user authorization.
- Agent history and resumable conversations; a separate inbox popup; a Cockpit-owned settings screen.
- Provider-specific mutations and a complete cross-provider Forge/Issue Tracker/Wiki feature matrix. Existing Jira lookup/import and supported provider read slices are not a claim of a complete provider matrix.
- Unbounded previews, arbitrary user-entered shell execution, and raw socket forwarding remain outside the product contract. Executing Herdr-advertised configured commands is supported.
