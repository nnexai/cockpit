# Cockpit decisions in force

This file records current product and engineering rules, not the implementation diary. Herdr and the repository are sources of truth for their respective state; UI details may evolve without changing those ownership boundaries.

## Herdr authority & compatibility

- Herdr owns live sessions, Spaces/workspaces, tabs, real terminal existence and membership, PTYs, processes, focus identity, and agent state. Cockpit does not keep a competing live registry. Space context selections record relevance, not live workspace authority.
- Use the supported Herdr socket/schema surface for persistent session state and terminal streams. Validate protocol, schema, and every required method before advertising compatibility; fail closed on mismatch. Display-version text is diagnostic and is not an exact patch-version allowlist. The adapter currently requires protocol 22, schema 1, and its required-method set.
- **Client-shell capability.** Native and browser hosts share the same session metadata, resource mutation and direct terminal contracts through the core/Herdr adapter. Custom command and popup discovery uses the generation-1 client-shell surface, with identity and mandatory codec checks. Negotiate optional `endpoint.surface-delta.v1` only with an advertised compatible codec and a complete bounded decoder; validate baseline revisions, dimensions and popup provenance before accepting delta metadata. Peers without this optional codec retain the existing full-surface path, not a protocol downgrade. `shell_unsupported` is a capability error, not permission to guess bindings. Disconnected/timeout/malformed/identity failures stay explicit; retired commands and popup targets reject invocation/attach with `command_not_available` / `popup_not_open`.
- Build client state from an authoritative snapshot and ordered events. On gaps, identity changes, reconnect, or stale state, resnapshot and rebind rather than guessing. A mutation acknowledgement is not itself fresh focus or control authority; that comes from the ordered Herdr state.
- **Tab placement.** Cockpit owns each tab's split tree of real terminals, local Files/Review/Browser viewer leaves and widget docks. Layouts live only in memory for the run, keyed by session, server instance and tab id; they are never persisted. Herdr rectangles, zoom and positioning hints are ignored. Dragging, divider resize, swap and zoom are local actions and send no `pane_resize`, `pane_swap` or `pane_zoom`. Terminal fitting still updates the attached PTY's grid.
- First load uses a balanced grid ordered by stable pane id. Externally created terminals insert at the full-height right edge, with share `1 / (existing leaves + 1)` including leaves hidden by zoom. Cockpit-created terminals are placed beside the acted-on leaf using Herdr's validated creation receipt, never inferred from focus or a snapshot difference.
- **Focus identity.** A changed Herdr focus triple (Space, tab, real pane) is followed unless it is the echo of a Cockpit request; zoom is restored if it hides that terminal. Repeated unchanged focus never steals selection from a viewer. Selecting a viewer sends no Herdr focus request. Layout selection, Herdr focus, attachment/input ownership and DOM focus are four separate states.
- **Membership.** Confirmed loss of a tab or its last real terminal, by close or move, retires its layout, releases Files/Review contexts and stops its Browser session. Durable comments and browser work remain. Loading, stale or disconnected state is never membership loss.
- Agents-list ordering is client presentation, as in the Herdr TUI: Herdr's API returns agents in workspace order, and the TUI applies its `priority` sort itself. Cockpit always uses that priority order (blocked, done, working, idle, unknown; newest state change first) and does not read Herdr's `agent_panel_sort` setting or plugin agent views.

## Terminal attachment & input

- Herdr owns the PTY and terminal model; xterm.js renders and captures input. Every terminal painted in the active tab attaches with `mode: control` at Cockpit's fitted grid; there is no observe attachment or downgrade. Input additionally requires DOM focus, Herdr-confirmed focus and owned control. Stable terminal frames and their sequence are authoritative; do not reset xterm on a full repaint.
- A tab switch attaches the target tab's painted terminals at Cockpit's grid before asking Herdr to focus it (up to 300 ms, released by the focused pane's first frame), and the old tab's terminals stay attached until the swap is painted. With no painted terminal there is no gate. Herdr resizes a pane on control attach and restores the TUI's size on disconnect; attachment eligibility is fresh membership in an existing tab, not Herdr geometry.
- Terminals hidden by zoom, an inactive tab or the Library detach without stopping Herdr processes or losing scrollback. Files/Review view state stays in the layout store; hidden Browser views release capture resources without closing the managed session.
- After a tab switch, DOM keyboard focus moves into the incoming selected terminal only once it is painted and Herdr has confirmed control; the terminal attaches hidden earlier, and a hidden element cannot take focus. Closing the Library by any route lets the selected terminal take focus after reattachment, except when restoring an explicit connected sidebar invoker.
- Keep ordinary terminal bytes on the attachment input path. Route wheel/page scrolling through the attachment's scroll operation and application mouse through the attachment's structured, cell-coordinate mouse operation when Herdr signals capture demand. Do not substitute raw SGR injection for structured mouse. Control intent, confirmed Herdr focus, attachment state, and process lifetime remain distinct.
- Attach, resync, and retry failures must leave the Herdr resource intact and visible with its status and recovery action. A request with an uncertain mutating outcome is not safe to repeat automatically; recover by inspecting authoritative state.
- When investigating mouse or terminal input, name the exact input path tested: **physical attach, xterm wheel, structured AttachMouse, or CLI-injected SGR**. State only the acceptance dimension observed for that path; evidence for one path does not establish another.
- **Server popup.** Render Herdr's singleton popup terminal as a centered floating surface above the existing split tree, respecting server size hints without inserting or reflowing leaves. Keep underlying painted attachments, make the underlay inert and gate ordinary pane input, including while a popup invocation is pending. Popup input uses the ordinary direct terminal transport with an explicitly validated popup target. Esc, Enter, Tab and prefix chords belong to its program; no local forced close or workbench shortcut runs behind it.
- **Popup lifetime and focus.** Only fresh authoritative popup metadata closes or replaces the popup. A stale/disconnected popup remains visible with input disabled, status and retry. On server closure let the eligible selected terminal regain keyboard focus; delayed opener restoration must not steal it. If no selected pane has regained focus, restore the available opener, else selected-tab chrome. Do not mutate Herdr focus merely to open or dismiss a popup.
- **Active shell geometry.** Accept the existing Herdr active 120×40 client-shell surface subscription required for command/popup metadata. It can resize unattached panes and a concurrent Herdr TUI; it is not a geometry-neutral observer. Direct control attachments protect painted Cockpit panes' fitted PTY sizes, and this subscription does not change Cockpit's split layout.

## Keyboard

- **Keyboard scheme.** Cockpit-wide shortcuts remain `Ctrl+B` prefix sequences on every platform. A key Herdr binds by default keeps its action meaning in Cockpit or stays unbound; Cockpit-only actions use keys Herdr leaves free. Deliberate difference: Cockpit does not implement Herdr-only built-in prefix actions (`s`, `q`, `e`, `[`, `o`, `Shift+G`, `Shift+R`). Pane cycling is `Ctrl+B Tab` / `Ctrl+B Shift+Tab` in local visual order. The static registry (`src/app/input/shortcuts.ts`) drives Cockpit Commands, tooltips and the generated keyboard-doc section; runtime custom bindings are a separate server-owned projection, not fake static entries.
- **Advertised custom commands.** Discover generic shell, pane, popup and plugin-action commands, their direct/prefix aliases and configured Herdr prefix chords from the identity-checked live server projection. Reload replaces bindings rather than retaining retired aliases. Invoke opaque advertised IDs with confirmed Herdr focus context, revalidating current command and membership; unknown actions stay unavailable. This is not a launcher-specific or plugin-private API integration.
- **Collision precedence.** Direct advertised chords precede local viewer shortcuts outside editors and local dialogs. A configured Herdr prefix arms advertised prefix bindings; Cockpit keeps `Ctrl+B` independently. When Herdr also configures `Ctrl+B`, custom prefix bindings win collisions with Cockpit actions; a different Herdr prefix does not redirect Cockpit-only actions. Commands/tooltips omit shadowed local shortcut labels. Literal-prefix passthrough is reserved before custom prefix lookup: `Ctrl+B Ctrl+B` sends a literal `Ctrl+B`, and a Herdr-armed prefix followed by a configured Herdr prefix passes the chord through.
- **Terminal claim set.** Except for advertised custom direct/prefix bindings and configured Herdr prefixes, a terminal or inline browser surface retains Cockpit's narrow claim set: `Ctrl+B` plus the next key, clipboard chords (`Ctrl+Shift+C/V`; `Cmd+C/V` on macOS) and `Shift+Enter`. Unbound plain `Tab`, `Shift+Tab`, Alt-, function- and Ctrl-chords reach the program. While a popup is open the workbench router yields entirely to its terminal.
- **Browser surface.** Prefixes and advertised bindings are recognized from the inline browser surface, not from its URL field or note editor; literal double-prefix passthrough avoids the keyboard trap.
- **Modal focus ownership.** Delayed pane autofocus must not steal focus from an open local modal. Portalled inputs do not select their underlying Files pane or invoke its shortcuts through React event bubbling; viewer handlers require actual DOM containment and yield to editable/modal focus.
- **Pane commands over the Library.** A pane-scoped prefix command closes the Library first, then acts on the selected pane.
- **Local pane commands.** Commands act on the selected leaf of any kind: splitting creates real terminals, focus/cycle/swap use Cockpit placement, and zoom is local. Viewers cannot move between tabs or Spaces. Esc restores zoom only on layout chrome; in a terminal, browser or viewer it belongs to that surface. Esc cancels an active drag.
- **Library close focus.** Closing the Library by its toggle key, toolbar button, Close button or Esc lets the selected terminal regain DOM keyboard focus after reattachment. Preserve an explicit connected sidebar invoker instead. A graphical originating pane regains focus if it is still selected. This changes DOM focus only, not Herdr focus.

## Workspace & filesystem ownership

- Setup opens a chosen directory by path or creates a worktree through Herdr's worktree API. Opening a checkout does not make it Cockpit-owned; an opened directory remains borrowed. Cockpit does not clone repositories or use display labels as filesystem authority.
- Cockpit owns operation records, Library content, durable Space Notes and per-Space context selections. Setup creates no companion directory. Existing companion folders and user notes are preserved untouched, including during teardown; exact operation receipts, not companion files, establish owned-worktree provenance.
- Destructive teardown requires explicit ownership plus the exact creation receipt and fresh checks of linked-worktree, endpoint, and clean status. Missing or ambiguous evidence never grants deletion authority. Preserve operation receipts across closed dialogs and uncertain responses; reconcile the recorded operation instead of dispatching setup twice.
- Keep filesystem reads bounded, rooted, identity-checked, and no-follow where applicable. Revalidate roots/source identity before mutations or returning comments: a path, label, or prior snapshot alone is not authorization.
- **Space Git actions.** Pull is strictly fast-forward-only, without rebase, merge commits or autostash. Push targets the existing tracked upstream with an explicit refspec, never force/mirror or upstream setup. Preserve normal Git credential and URL-alias configuration; never expose remote URLs in status or diagnostics. Fetch mappings must not mutate local branches before the fast-forward decision.
- **Git targeting and uncertainty.** Row actions target their explicit Space without changing selection; Commands targets the selected Space, including worktrees. Fresh Herdr checkout authority, filesystem/Git identity, branch, upstream and effective remote destination must still match after queued work acquires its reservation. Pane-folder status grants no write authority. Counts are last-fetch knowledge, not remote freshness. Ambiguous spawned failures remain unknown and are never automatically retried.
- Setup is plan-driven and path-only for Open. The plan is tied to its input; stale plans require a fresh user start. Provider links may identify/import artifacts but do not select or clone a repository on the user's behalf.

## Supervisor orchestration

- **Ownership and task-first UI.** Cockpit owns durable task intent, run relationships, plans, grants, reports, inbox delivery receipts, task-assignment journals and acceptance intents. Herdr remains authoritative for live process/resource membership, location and agent state; join fresh snapshots rather than persisting live status. Supervisor lives below the tab strip alongside the Library, without a fake Herdr pane or tab. Start agent defaults to a fresh OMP tab in the current Space without switching terminal focus; Existing Space, Directory and Dedicated agent folder are available under Start options. Give work through direct terminal conversation; the bottom Task composer and its resize handle are removed. Agents, History and Diagnostics are secondary; the supervisor handles delegation/preparation/execution/review and escalates only genuinely missing decisions.
- **One task source.** `<state_root>/orchestration/tasks/<root_id>.md` is canonical for title, Markdown body and checked state, with stable UUID markers. Task states are a projection, not a copied-card store or Herdr task integration. Lanes derive from checked state and the current run; blocked is an overlay. External edits remain authoritative, exact-byte task/document revisions fence writes, unmarked items need ID assignment and duplicate IDs block mutations. TaskAssign publishes the canonical item and one root-inbox task pointer through a recoverable cross-document journal with one stable UUID. The journal temporarily retains submitted title/body until both are committed, not as a second task authority. Authoring alone is not assignment; conflicts require exact-revision resolution, never Markdown rollback.
- **Forest, not one agent queue.** Multiple supervisor/adopted roots and unmanaged agents are legitimate. Delegation edges are independent of Space location. Actual internal OMP subagents publish parent/role/lifecycle telemetry without creating panes. Keep reported progress/results, annotations and fresh Herdr status separate with source/time provenance; a subagent report must not replace its main run's initialization/result receipt.
- **Supervisor-authorized Prepare before Execute.** Proposals return without waiting for workers. Explicit repository worktree, Open path or existing-Space targets reuse project setup plans/operation receipts; routing is configured or based on actual forge-origin suggestions, never cwd/current Space. The actual main OMP session of a freshly bound, active, top-level Supervisor or Adopted root may authorize only strict descendant Worker runs; workers/subagents cannot self-authorize or control siblings, ancestors or other roots. Single-use Prepare binds the exact reviewed setup revision and permits setup/launch plus bounded read-only initialization in a real new tab. The prepared worker reports Ready with an exact work plan and retained initialization receipt. The root reviews that plan before granting Execute at its exact revision; changed plans require fresh review. Routine operator confirmations are not required. Advanced browser/native operator grants remain supported; supervisor grants record their own origin and actual root/session provenance, never forged operator authority or widget-selection approval.
- **Actual launch proof and policy, not sandbox.** Herdr `agent.start` ACK is pending only. Fresh actual OMP evidence and the main SDK-session binding are required before Active/Launched; working OMP is valid and an interactive-ready label is not mandatory. Fresh run/attempt, endpoint/terminal and native OMP-session identity fences prevent accidental stale or mismatched actions. The per-process OMP extension blocks mutating tools, shell/eval and delegation before Execute. Same-UID filesystem/socket access remains broad authority; do not describe these gates as hostile-agent isolation or an OS sandbox.
- **Pull delivery.** Persist briefs, instructions, answers and reports as inbox messages. OMP receives only a counts-and-pull wake: non-steering `aside` starts an idle turn, and busy wakes coalesce as `followUp`. The main session pulls untrusted bodies and explicitly acknowledges only after processing. Stored, Woken, Read and Acked are distinct. Never type orchestration content into terminals, submit user drafts, or use Herdr prompt/callback steering. Internal subagent Send uses native external Cockpit IRC, never impersonates parent IRC or steers; Cancel terminates the exact child's native task lifecycle and owned background work, awaiting disposal rather than only aborting its turn. Applied/failed receipts record these native outcomes; unknown control effects are not silently repeated.
- **Bound-session inbox tools.** Prefer `cockpit_inbox operation=list`, process the returned untrusted bodies, then `operation=ack` through the processed sequence. The SDK tool supplies fresh native-session identity and the launch-selected CLI/configuration; do not rely on an older ambient-PATH `cockpit-cli`. Direct CLI pull/ack is supported when executable, configuration and caller evidence match the run.
- **Reporting is not acceptance.** Progress, Ready, NeedsInput and Result are explicit reports; only the bound main OMP session may file Ready/Result. Workers may append upward to any ancestor (parent by default) without upward control authority. Idle/done/exited without a Result is missing-result attention, not success. Result enters Review without checking Markdown. The authorized supervisor reviews an explicit successful Result and Accepts it at the current exact task revision through the API; no automatic acceptance from runtime state or report delivery. Advanced operator acceptance remains available. Send back returns work for further execution. Neither acceptance nor cancellation deletes resources.
- **Durability and uncertainty.** One locked, atomically replaced `orchestration/state.json` stores machine records, with recoverable assignment and acceptance intents across it and Markdown, not a second canonical task store. External editors ignore the lock; byte rechecks still leave a final recheck-to-rename race. Dispatch runs only in the private runtime owner with per-run execution leases; owner restart preserves orchestration records and Herdr processes. Record launch intent before creation and reconcile exact endpoint/receipts/tags after uncertainty. Explicit recovery/retry is not permission for automatic re-launch or repetition of external writes; there is no cross-process/external-effect exactly-once guarantee.
- **Launched-run recovery.** Check status/Reconcile is a read-only exact-receipt review, not another setup/launch. Fresh matching actual OMP proof and binding restore dispatch Launched while preserving current lifecycle, initialization/result receipts, grants, location and inbox progress. Missing terminals, stale bindings or conflicting proof remain visible as missing/Unknown/NeedsReview; unavailable observation does not establish absence. Only explicit guarded Restart/Retry launch rechecks the old launch and creates another tab, retaining run/root identity and setup while incrementing the attempt and requiring a new native main binding. Fence the review result to its queued request, launch incarnation, location and binding—not an unrelated global revision or stale lifecycle snapshot. Never implicitly duplicate a possibly live agent. Close tracking retains tasks, accepted results and history and does not guarantee stopping the agent or descendants.
- **OMP installation and native CLI pairing.** Load the bundled extension explicitly with per-process `-e`; do not mutate global OMP configuration, install it globally, or manage authentication. Reuse existing authentication. Explicit `CliProcessRole::Host` permits the host to use itself; `CliProcessRole::Native` selects the paired CLI, so the installed GUI named `cockpit` must use sibling `cockpit-cli`, never itself. Debug `cockpit-tauri` may use the distinct sibling `cockpit` host. No override is needed for the installed pair. Supervisor task documents live outside worker checkouts; Space context reads the live Library and existing repository paths directly, with no companion creation/copy/teardown.

## Context & Review

- Files, Review and Browser are Cockpit-owned tab-local viewers, at most one of each kind per tab. Opening an existing viewer focuses it; Files/Review switch to the requested source and retain per-source view state. Viewers never launch addon TUIs and have no terminal/renderer toggle. Existing addon panes remain ordinary Herdr terminals.
- Files/Review use a core-issued viewer context and source binding opened from a real same-tab terminal. Authorization pins the selected source root, cwd, endpoint, tab and Space, then rechecks fresh tab membership, binding and filesystem identity on each request. The source terminal may subsequently close or change cwd without retargeting the viewer; unrelated roots never become authorized through it.
- Context and Files use Cockpit's bounded filesystem model. Context reads the live Library and freshly authorized local checkout roots without a companion. Same-tab viewer bindings, endpoint/Space identity and no-follow filesystem identity remain mandatory. Unsafe, stale, oversized, or unsupported sources fail closed.
- Review is Cockpit's read-only local Git view plus shared comment capture. Comments retain immutable source identity/line anchors, and source state is re-evaluated before a successful save or delivery. Stale or uncertain deliveries retain recoverable drafts/receipts and never submit Enter to an agent.
- Comment ownership is tagged `viewer` or `legacy_pane`; source identity and authorization remain mandatory for save, reattachment and delivery. Comment batches and paste receipts are run-local: view closure does not delete them, but the next owning-runtime startup clears the pane comment store.
- File-picker indexes are hints only: server authorization is checked on each request and each fresh open re-enumerates the root. Git indexes exclude ignored files; other roots use a bounded no-follow walk. Persisted XDG-cache data contains paths and metadata only, never file bodies or authorization evidence; `COCKPIT_CACHE_ROOT` overrides the configured `cache_root`.
- The picker list is eventually consistent without user action: the viewer warms the client list in the background on root open and window focus (30 s throttle), an open picker shows the cached list at once, replaces it with the fresh one, retries failures with backoff, and quietly revalidates every 8 s while indexing stays under 2 s. A slow index only changes the status text; it is never aborted or left as a dead end.
- Review snapshot reuse requires matching current revision tokens, repository/source/comparison identity, and resolved branch merge base, and is skipped for any snapshot that contains untracked files (their tokens are metadata only, so a same-size rewrite that keeps its mtime would look unchanged). The versioned viewer-bound snapshot must still load before an in-memory reuse hit is returned. Recognized pre-viewer cache filenames are pruned without deserializing their obsolete payloads; malformed current-format cache data remains an error. Git digest commands stream stdout under the normal process timeout.
- The repository catalog scan may be served from a bounded in-memory cache on read-only Context/Files/Review paths (fresh 30 s, stale up to 5 min with a background refill, invalidated on any Cockpit store mutation). Per-directory checkout discovery is never cached: it decides which checkout a runtime path belongs to, so it always runs on the original path (no symbolic links, current Git boundary). Setup, plan, resume and teardown checks never use the cache.

- The global Context Library is a Cockpit-owned view below the tab strip, not a Herdr pane, tab, or synthetic resource.
- With no session loaded, the view is Library-only: there is no target Space or pane authority, and Space actions are absent. Opening or closing the view never asserts Herdr focus, pane selection, or process authority, and never changes a tab's local layout. Membership and focus reconciliation continue while it is open.
- While the Library view is shown, visible pane renderers and live output subscriptions are unmounted; closing it lets the selected tab's panes attach/resynchronize. Do not keep hidden terminal renderers or subscriptions mounted for the Library.
- **D13 focus policy:** on open, move DOM focus into the selected/first Library tree row. On close, restore an explicit connected sidebar invoker; otherwise let the eligible selected terminal regain keyboard focus after reattachment. Restore a graphical originating pane when it is still selected, or safe workbench chrome when no eligible pane can take focus. Closing never sends a Herdr focus request.
- Pasting a prepared comment targets an explicitly selected eligible agent in the same actual tab. Preparation and send validate current payload/source; preview is optional, and sending does not submit the terminal command. Keep pending, rejected, and unknown outcomes distinct to avoid accidental duplicates.

## Agent widgets

- Widgets are Cockpit-owned, run-local dock content, not Herdr terminals or durable Library/context files. Many IDs share one tab-local dock (eight live maximum); the exact session/tab/ID and source authority distinguish each widget. Same-key show updates in place without selecting the source, switching tabs, asserting Herdr focus or sending terminal input. Confirmed tab/final-terminal loss and owning-runtime shutdown retire widgets; stale/disconnected state does not.
- The existing private owner runtime hosts the in-memory `WidgetService`; CLI show connects to that owner and copies bounded regular no-follow file, stdin or choices input, never registers a live file watch. Browser HTTP/WebSocket and native IPC/channels share the content/select/remove/event contract. Resolve destination and source against fresh Herdr endpoint/session/membership evidence. Inside Herdr, contextual current-pane source remains separate from explicit destination; outside it, require explicit pane/tab/Space and session/socket targeting, without guessed agent attribution.
- Respect **Remove**: a user tombstone blocks ordinary same-ID show. Only an explicit user request permits `--reopen`; changing IDs is not a removal bypass. Reopen starts without selection; replacement preserves it unless `--clear-selection` is requested. Agent close is idempotent. User removal restores DOM focus only if the outgoing dock owned it; agent close, retirement and snapshot removal do not move DOM focus.
- HTML executes trusted author scripts and event handlers in an active opaque iframe (`allow-scripts`, no `allow-same-origin`), with ordinary HTTP(S) scripts/resources and standard network access allowed. Host CSP and removal of author base/http-equiv policy prevent ambient host schemes/APIs, nested frames, workers, objects, base overrides and form submission. This is a narrow ambient-host-privilege boundary, not perfect security or CPU/memory/network/process isolation; busy JavaScript can freeze native Cockpit, while Herdr terminals persist. No separate widget webview, Chromium process or image stream is involved; the Browser viewer is unchanged.
- Fragment-only links targeting the widget itself are resolved against `about:srcdoc` at ordinary click/Enter activation, not the embedding Cockpit URL. Native fragment scrolling, focus, `:target` and history remain browser-owned; author handlers can cancel navigation. Modified clicks, downloads, other targets and external/document links retain their existing navigation and sandbox policies.
- `cockpit.select(value)` records untrusted JSON for CLI pull/wait only; it never chats, pastes, focuses a terminal or writes terminal bytes. Accept only the current widget key/revision and exact frame source/per-incarnation nonce, at most four UI submissions per second. Enforce raw and canonical selection UTF-8 at 16 KiB, HTML at 1 MiB, aggregate owner HTML at 64 MiB, and owner/transport snapshot metadata at 8 MiB. Retained selection is returned as a full nullable selection response with content; page retained state is a mount/replacement snapshot.
- The bounded iframe keyboard bridge routes Cockpit/configured Herdr prefixes and advertised custom bindings into the existing workbench router, never a synthetic typing/paste path. Selection values remain data: validate shape and allowed values, handle none/timeout/dismissed/retired, and never execute or splice them into commands or instructions.

## Space Notes

- Notes is a local Space workarea, not a Herdr pane, Library item, checkout sidecar or agent widget. Header/Commands entry changes only Cockpit's presentation. Scratchpad, Todos, Kanban, Decisions and board-item comments use the same typed core operations through CLI, HTTP and native IPC.
- Store ordinary Markdown under a durable Notes UUID at the configured `notes_root` / `COCKPIT_NOTES_ROOT`, defaulting to the OS data directory's `cockpit/notes`. Keep this root outside disposable worktrees, the Library and Cockpit's ephemeral pane-state roots. Opening never implicitly creates or attaches content; setup/teardown and browser startup reset do not manage this store.
- Bind by live endpoint boot identity, session and Space ID. Labels and checkout paths are display facts only. Herdr restart requires explicit reattachment of preserved content; transfer is explicit and confirmed. Agents resolve from a real current pane once, then pin `--notes UUID` and the Notes root; pinned content access does not require Herdr or an owner process.
- One `todos.md` owns both the list and board. Hidden stable IDs and optional Backlog/Doing metadata establish membership; the checkbox establishes Done. Reopen restores the remembered open lane. All moves preserve canonical source order; unboard retains the todo and comment thread.
- Decision replacement creates a new linked record and leaves the old file unchanged. Decision recorded timestamps and comment creation/author metadata are immutable through Cockpit edits. Author labels are optional, unverified text, not authenticated identity.
- Preserve source bytes with bounded no-follow reads, revision-checked surgical edits, stable advisory locks and atomic publication. Refuse stale, malformed or ambiguous writes rather than guessing. External editors that ignore the locks can race after the last check; no filesystem-wide CAS is promised.
- Keep scoped drafts and editor state across view/Space changes and Notes closure. Conflicts need explicit resolution; unknown write outcomes require a saved-state read plus an explicit may-duplicate acknowledgement before further writes, never automatic replay. Pointer/keyboard moves capture identity and revision; cancellation, source changes or loss of the owning view never retarget them. Keyboard intent is captured before the sensor's deferred listener/collision refresh.

## Inline browser

- Browser is a Cockpit-owned tab-local viewer with one independent managed session per Herdr tab, not a Space sidecar or Herdr pane. Tab switch, zoom and Library hide its view. Closing the viewer, losing the tab's last terminal or shutting down its owning runtime stops the session and removes only its proven Cockpit-owned profile and launch artifacts. Cookies, logins and site storage are disposable; cleanup failures remain visible and retryable.
- Creating/reopening a Browser leaf uses `OpenFresh`: surviving sessions are stopped and cleaned, never adopted, and the new session starts at `[browser] default_url` or `COCKPIT_BROWSER_DEFAULT_URL` (default `about:blank`, validated at configuration load). CLI `Open` and an existing leaf's Reconnect retain their attach/new-page semantics.
- **Ephemeral pane state.** Browser sessions/profiles, annotations, drafts, pending captures, feedback and delivery receipts, Files/Review comment batches and paste receipts, and Review scratch caches last for one owning-runtime run. Only the process that acquires the exclusive browser owner lock resets these stores, before publishing its socket or constructing dependent services; observers never reset an active owner's state.
- **Startup reset.** Stop proven leftover managed sessions first, then clear `browser/` except `owner.lock` and `owner.sock`, plus `comments/` and `review/`. Preserve the lock inode; use no-follow, same-device deletion limited to these pane-state roots. If shutdown cannot be confirmed, fail startup without wiping browser state. Never touch Library or Notes content, credentials, configuration, project operations or real Herdr sessions/terminals.
- Closing/reopening fresh, tab/final-terminal retirement and owner shutdown discard the outgoing browser association's work as well as its profile. Saved-tab/archive recovery APIs, reviewed legacy-file panels and saved-work close guards are removed. Current-run cleanup failures stay inline and retryable. Browser cleanup requires confirmed shutdown, derived paths and identity checks; the CLI targets `--tab` or `--current`, never detached `--legacy` work.
- Unsent notes and annotations belong to the page/document they were created on. Navigation retires that page's drafts; drafts for other open tabs and drafts referenced by a prepared capture remain only within the current run and live association. Preserve current-run delivery reconciliation; unknown outcomes are not automatically replayed.
- Preserve target, document, viewport, and ownership checks for input and captures. A capture must refer to the pinned frame and immutable submitted image; do not turn incomplete or lower-density live imagery into saved-frame evidence.
- **Accepted requirement, implementation/acceptance not verified:** attempt sharp browser images when safe and affordable, but allow lower resolution to preserve responsiveness during animation, hover, or scrolling; pursue affordable quality again as activity eases. Do not freeze older sharp imagery, poll continuously, or weaken frame/target/lease checks. Measure Chromium capture separately from Linux WebKit display/input. See [Live browser image quality](planning/stability-and-gitlab-2026-09-20/ACCEPTANCE.md#live-browser-image-quality).

## Providers & setup

- Provider adapters expose supported capabilities and explicit unsupported-operation errors; Cockpit reads/imports and validates provider data, while remote writes remain with provider CLIs or the user's usual tools. Provider metadata may inform a plan but does not override local repository choice or Herdr ownership.
- **Atlassian HTTP cutover (2026-10-06).** This supersedes the Jira CLI, Confluence CLI allowlist/profile and credential-fallback decisions. Every provider requires explicit `kind`; executable/id inference is removed. Only GitHub/GitLab/Gitea retain required `executable` and optional `login`. Jira/Confluence reject both and use only the token stored in Cockpit's OS vault. Their optional `deployment` resolves from an explicit override or case-insensitive `*.atlassian.net` → Cloud, otherwise Data Center; auth kind never selects deployment. Confluence Cloud requires exactly `/wiki`, and Data Center context paths are preserved. Jira Cloud v3 enhanced-search token paging, Jira DC v2 offset paging, Confluence Cloud v2 and DC v1 share a pooled GET-only transport; no remote write methods exist. JSON redirects are same-origin and end on-site; downloads can redirect cross-origin without Authorization, with three-hop and HTTPS-downgrade limits. Continuations rebuild validated endpoints, never follow JSON URLs. Confluence storage XML converts locally to Markdown for both deployments; explicit refresh may change old rendered bodies, but unchanged follows do not mass-rewrite. No compatibility shim or automatic user-config editing; current migration examples are in `CODE_GUIDE.md`. Historical CLI live evidence does not verify this HTTP cutover; a new stored-token live run is still required, with Data Center and macOS vault live limits reported separately.
- Current setup supports configured local repositories, path-only Open, Herdr worktree creation, and configured artifact lookup/import including Jira work items. Jira lookup uses Cockpit HTTP against the configured site; string (wiki-markup) bodies from self-hosted Jira are converted to Markdown while ADF bodies keep their own path. A Jira URL or ticket key never chooses or clones a repository. Imported artifacts are bounded and validated before setup; setup does not follow references (that is the Library `reference_depth`).
- Prefer explicit, bounded hydration and canonical snapshots with source identity/revision where available. Freshness checks use provider metadata when available and canonical content otherwise. A failed optional import should not erase successful assets or silently become a successful import. Following references is one explicit `reference_depth` (see the reference-depth bullet under Library decisions), never a per-provider boolean.
- Generated issue-like Library documents use frontmatter for known provider facts and a title/summary followed by optional Description and chronologically ordered Comments sections. Comments are Markdown cards with stable local timestamps, provider permalinks, edited timestamps only when changed, and provider headings demoted beneath document/card headings; partial lists retain shown/total counts.
- Configuration comes from supported file, environment, and invocation options. Secrets never enter context snapshots, generated environment values or configuration files; see the Provider credentials rule.
- Provider imports are authorized by the selected configured provider instance and the artifact's validated canonical identity/URL, not by a checkout's Git origin.
- **Provider credentials.** Cockpit stores one pasted API token or PAT per configured provider id and instance (`base_url`) in the OS vault (Linux Secret Service; macOS Keychain is compiled but unverified), keyed `cockpit` / `<provider id> <instance>`. Changing `base_url` never re-targets a stored token; adding explicit `kind` preserves the account identity. Only Jira and Confluence support it (`Bearer` or `Basic` with a username); glab, gh and tea report `unsupported`. The client boundary is write-only: set, clear and presence/kind status, with no read path and no secret, username or vault detail reaching the frontend, logs, errors, argv, Library files or configuration. Jira/Confluence have no credential environment injection or CLI fallback: no token → `source_credential_required`; vault failure → `credential_vault_unavailable`. Authorization is sent only to the configured origin; cross-origin binary media hops carry none and HTTPS downgrade is refused. Vault calls time out at 20 s; per-process caching means external Seahorse/KWallet changes appear after restart. Forms default from resolved deployment (Cloud Basic, Data Center Bearer), retain the stored replacement kind, and keep both selectable. Missing tokens show `No token stored`, vault failures `Keyring unavailable`; removal prevents reads until a token is stored again. Passkeys/WebAuthn and OAuth sessions are not storable secrets. Historical Jira/Confluence CLI/private-keyring live runs are not HTTP acceptance; Data Center Bearer and macOS Keychain remain not live-verified.
- The Library is the durable global source: add and refresh save there first. Each Space selects relevant Library item IDs and additional configured local repository paths; no files are copied, versions pinned, or Space copy/update/retry state retained. Library refresh is visible on the next read. Selection is not access control. The Library is managed/read-only by convention; writable Space Notes use their separate durable Markdown store.
- **Eventual Atlassian synchronization (2026-10-06).** Changed-since Jira/Confluence discovery is part of the initial implementation, not an optional optimization. Default hourly fixed windows have five-minute lag and thirty-minute overlap; complete discovery durably enqueues candidates before committing its upper boundary. Fetch failures retain independent retry/backoff across checkpoints and restarts. Daily complete inventories reconcile membership/hierarchy and tracked accumulation keys; rolling seven-day auxiliary audits cover changes not reliably represented by page/issue revision metadata. Standalone inventories persist their frozen cohort, cursor and cumulative observations across budget exhaustion; incomplete chunks never grant absence authority.
- Only long-lived native/`cockpit serve` runtimes start synchronization, with one owner per Library root and no closed-app daemon. Per-origin background defaults are 1 request/s, 2 in flight and 1,200/hour, with interactive priority and cooldown handling. Preserve configured Library/import limits, local edits, retaining refs and explicit exclusions. Quiet checks do not rewrite index/snapshots or add operation receipts; incomplete attachment manifests do not replace existing binaries. Revalidate follow/exclusion authority at locked publication after asynchronous fetch/download waits.
- Open Library/context listings observe backend generations through bounded first-page checks while visible; read all pages only for a changed generation. Global primary preview selection follows stable item identity through a rename and invalidates on its own snapshot revision, not unrelated index changes. Background notifications remain distinguishable from manual refresh events, and bound file/comment authority is not retargeted.
- Local folders are explicit typed-path captures into the Library, never live links. Capture uses canonical no-follow roots, rejects all overlaps with Cockpit-owned roots, excludes and counts unsafe/special files, and reports configured file/byte limits as sorted partial copies. Re-copy is explicit and preserves edited Library bytes behind CAS. Selecting an additional repository reads its existing checkout in place and never captures it. Existing companion directories and unknown files remain untouched; only known Library-backed legacy association metadata migrates to selections. `<state_root>/sources` remains inert.
- The Library disk layout is readable without Cockpit: real nested directories mirror each source's hierarchy (`<provider>/<host>/…/<leaf>/<Title>.md`, attachments in `_files/`), titles are kept except unsafe characters, and all machine state stays in `.cockpit/`. Moves are directory renames, never copies. There is no migration from the flat layout (index schema 1); such Libraries are wiped and re-added. Index schema 2 (nested layout) upgrades to schema 3, then schema 3 upgrades in place to schema 4 through raw-JSON migration: journal references/intents are rewritten before the index schema flip, making migration rerunnable. Schema 4 retains unknown legacy Space references as opaque IDs that protect content from garbage collection unless an exact fresh legacy association maps them to a current Space. Migration is one-way; older binaries reject newer schemas. Wipe-and-re-add was rejected because live Libraries hold Confluence follows.
- Markdown links resolve only inside the currently authorized root; source URLs open the Library item. Comments and paste retain real paths. New terminals receive `COCKPIT_LIBRARY_ROOT`; existing terminals use the read-only `cockpit context --current` discovery command.
- **Atlassian read and attachment contract.** Page/issue identity belongs to the selected, validated configured instance; ambiguous authority fails closed. Jira HTTP reads map `fields.attachment[]` to bounded metadata, and Confluence HTTP reads capture attachment metadata with page snapshots. No binary download happens by default. Explicit per-item or opted-in follow downloads use the shared HTTP transport, validated ID-based links, private no-follow staging, enforced per-file/aggregate byte budgets, safe stored names and atomic publication; partial files are removed on error. Jira metadata stays on `/rest/api/2/attachment/{id}` on both deployments and must prove the requested attachment identity before its on-site `content` link is downloaded; the stored `source_url` is not trusted. Confirmed Library replacement re-downloads edited bytes only after matching exact current hashes; opted-in follow refresh retries failures. Only PNG/JPEG are active media; PDF has no renderer and SVG/HTML are not executed. Missing stored credentials fail without external-login fallback. A Jira follow's download opt-in saves successfully read issues and reports per-row download failures. Historical fake-server checks are not a live attachment claim; a live Jira attachment download and Data Center behavior remain unverified.

- A Confluence space follow is a snapshot of every readable page across the space, including separate top-level trees; Cloud folder ancestors are hierarchy nodes, not page documents. Manual refresh retains concurrent lookups and a bound of eight changed-page fetches, with deterministic parent-first crash-safe commits. Automatic refresh uses the background synchronization policy above. Only complete enumeration plus per-page confirmation may mark pages removed at source. Partial, failed, or cancelled enumeration does not infer absence or mark pages removed. Excluding a followed page persists until the entire space is followed again; stopping a follow keeps its pages as ordinary Library items.
- Space context has no separate follow-copy state. A Library add targeting a Space selects the saved items; later global follow refresh changes the live Library, not the selected ID set. Removing a selection never deletes Library or repository files.
- **Reference-counted Library items.** Every item carries a sorted, deduplicated `refs` set (`Manual`, `Follow{follow_id}`, `Space{space_context_id}`) that replaces the old single `follow_id`; a pin is just a `Manual` ref ("Keep in Library"). Refs change only through `mutate_index` under the exclusive lock (plus the birth ref of a new item); publish, update and journal replay keep the index's current refs and purge time, so concurrent follows cannot lose each other's membership. An additive `#[serde(default)] refs` was rejected because an empty default means "unreferenced" and would tombstone every migrated item. An item with no refs gets `purge_after` and is deleted by the sweep at the end of every add/refresh once due, unless it is leased or has local Library edits. A live follow drop waits 14 days (`TOMBSTONE_GRACE_MS`, not configurable); explicit removal (Remove follow with items, removing the last Space selection) is due at once. Consequence (Q5): a page that was added manually and later covered by a followed Confluence space survives removing that space because it holds `Manual`; migrated data is unaffected because v2 members map to `Follow` only.
- **Jira query follows.** A follow is normalized JQL (a bare project key means `project = KEY`) in mode `live` or `accumulate`; its id hashes provider, instance and JQL with the `follow:` prefix. Each issue is one item, keyed by provider, instance, `issue` and key, shared across follows at `jira/<host>/<PROJ>/<KEY>/<Title>.md`. Issue and listing reads use Cockpit HTTP only, with Cloud enhanced-search tokens or Data Center offsets, 100 results per call and the configured `library_space_pages` cap. Full/manual listings order by `updated DESC`; background deltas use fixed epoch-millisecond bounds and deterministic `updated ASC, key ASC`. Content is fetched for changed, removed, failed or unknown items; item metadata (`issue`) never enters `content_revision`. Manual live refresh keeps members on failed, truncated, cancelled or empty listing; background absence reconciliation additionally requires repeated complete inventories and confirmation. `accumulate` never drops and refreshes tracked keys omitted from the full predicate; it remains the default for relative-date queries. An incomplete run remains partial and never grants removal authority. `Stop following` keeps items (exclusive members become `Manual`); `Remove query and its items` deletes only exclusive members and is refused on local edits. Attachment bytes use the stored token, per item or by a follow's opt-in.
- **Reference depth.** One `reference_depth` (API 0 to 5, `library_reference_depth_invalid` otherwise; UI `Follow references`: Off/1/2/3) replaces the boolean `hydrate_references` and the same-repository forge crawl, with no alias. Defaults: single Jira issue 1; forge issue/PR, new Jira query and any stored item or follow without the field 0 (additive `serde(default)`, no schema bump). Confluence page adds and space follows reject depth above 0; folders ignore it. References are Jira structured `parent`/`subtasks`/`links` frontmatter fields (chosen over a new `SourceAsset` field, which would touch every provider literal) plus Jira keys and URLs in description and comments and URLs in other bodies. A URL is followed only when it resolves under a configured provider instance (Jira, Confluence pages, GitHub/GitLab/Gitea issues and PRs) with the direct-import authority checks; reached items expand at the same depth by the same rules regardless of provider, and Confluence spaces, unsupported and unconfigured URLs stay links. Traversal (`SourceService::collect_related`, fetch-only) is breadth-first, deduplicated by canonical Library identity so cycles collapse, eight fetches in flight, at most 64 references per asset, with internal non-configurable caps: single import 32 related items/8 MiB/60 s, query follow 100/16 MiB/180 s. Seeds are saved before traversal; a failure, cap or cancel is a Partial row, never touches seeds and never authorizes a drop. Storage keeps one `included_by` reason per holder (shallowest route, relation, step); Details renders each distinct reason once (the UI deduplicates identical rendered reasons). Single import: depth persists on the seed and each explicit refresh re-traverses; related items get `Manual` plus a seed-held reason, so they survive seed removal and a complete refresh only strips the reason. Rejected: a new seed-held ref kind (the set only grows, like accumulate, and the boring model matches the old linked items). Query follow: related items get `Follow{F}` plus a follow-held reason; an item the query lists is a seed and drops the reason; a live follow drops unreached related items only after a complete related pass and complete listing, accumulate never does; unchanged seeds are traversed from stored `references`, and old seeds without them are refetched once. Space independence holds: refresh never fans out, Jira follows stay out of Spaces, a single add targeting a Space selects what that add saved. Live-verified only for a Jira and Confluence graph (SCRUM-7 to SCRUM-9 with a cycle: depth 0/1/2 saved 1/3/4 items, JQL depth-1 follow and refresh correct); forge URL expansion is fixture/contract verified, not live.
- Jira follows remain global Library query collections, not per-Space follow state. Individual Jira items can be selected as direct context. Query refresh does not silently change a Space's selected item IDs.
- **Library tree grouping and nesting.** The tree is provider instance → container → item, and every level is keyed by provider id and instance, never by host: Jira and Confluence on one Atlassian site are separate instances. A Jira query follow is a container under its own provider only, and an item another provider pulled in through a followed reference (a Confluence page linked from an issue) sits in its own provider's container, not under the query. A follow row shows its query (or space) as its name, ellipsised only on overflow with the full text as tooltip, and puts `Following` and its count on a second line. A Jira subtask nests under its parent issue when the parent is in the same container; otherwise it stays a top-level row. The parent is the stored `parent` reference of the issue's document, projected into `parent_item_id` by the listing only: the stored `parent_item_id` of a Jira issue stays empty because it decides the on-disk layout. A copy saved before references were captured has no parent until it is next fetched. Siblings keep the issue order (newest key first).
- **Library tree keyboard.** The tree has one tab stop (the row that last held focus, else the selected row, else the first). ↑ ↓ Home End move focus; → expands a group or enters its first child; ← collapses or moves to the parent; Enter opens an item and toggles a group; Space is the row's own click; Shift+F10 and the Menu key open the row menu. A navigation key pressed while focus is on `<body>` (a button that disabled itself, a closed menu) takes the tab stop back, so a refresh or dialog never leaves the arrow keys dead.

## Subscription limits

- Quotas are read-only OMP-owned data: one usage report supplies Codex, Claude, and Copilot, including Copilot Business. Cockpit does not acquire/store credentials, run sign-in, switch accounts, redeem credits, or invalidate OMP's cache. OMP authentication may have its own refresh side effects. No separate GitHub CLI quota collection remains.
- OMP's `copilot:premium` quantities are the Copilot AI-credit counters, copied without conversion or scaling even when OMP labels their unit `requests`. Unrelated chat/completion counters and unsupported units are ignored. OMP JSON omits billing flags, so Cockpit does not independently distinguish legacy request-billed accounts; OMP remains the accounting authority.
- Native/browser runtimes sharing a configured cache root share one OMP schedule, a cross-process lock, and a persisted pre-command lease. Schema 2 rejects obsolete split-source snapshots while retaining the `quota/v1` lock. Collection is demand-driven: at most once per five minutes while idle, or once per minute after completed success when a visible client reports a live working agent in its selected Herdr session. Working demand never shortens the five-minute crash lease or 5/10/20/40/60-minute failure backoff. Older snapshots without positive success evidence keep their existing deadline. OMP's five-minute report cache with jitter still bounds source freshness and is never invalidated. Cache failure never permits a process-local collection fallback.
- Persist and transmit only allowlisted quota data and anonymous accounts. Preserve source observation times; failed or over-15-minute-old values are visibly stale, and over-24-hour-old values are unavailable. Missing windows, unknown quantities, zero balances, and unlimited entitlements remain distinct.
- Use the existing 28 px work-area strip, not another footer. Show used percentages for every reported tier/window, taking the highest usage across anonymous accounts for each window; Copilot also shows a percentage, preserving small values such as 0.05%. Narrow layouts retain all windows for the selected provider plus a count of other providers. Details show used values, including unscaled AI-credit counts. Mouse hover previews read-only details without taking keyboard focus; leaving the strip/popup or pressing Escape closes the preview. Click, Tab/Enter, or Commands pins details open, with normal opener restoration on Escape; no dedicated chord. Used-quota meters and values are amber above 80% used and red above 95% used (strict thresholds), independently of provider-reported levels; stale hatching remains muted. Hidden clients pause reads; visible clients poll status every 15 seconds while live agents work, every 60 seconds otherwise, and every 3 seconds during collection.

## Sidebar presentation

- **E1.** The sidebar keeps Herdr's hierarchy, order, urgent-state rollup, lowercase section labels, two-line agent rows, branch line and trailing repository chevron. It intentionally differs in these ways only: (a) worktree children show a shortened name (Herdr label or branch without a leading `worktree/`, `worktree-` or repository segment) with the full name and checkout path in the tooltip; (b) the second line of an agent row is `State · agent` instead of the agent name alone; (c) status marks are drawn as SVG badges, a state-tinted disc with one of five distinct shapes, instead of text glyphs.
- **E2.** Sidebar keyboard navigation (arrows, Home/End, ←/→, Menu key) moves DOM focus only. A Herdr focus request is sent only by Enter/Space or a click, and selection chrome follows Herdr's acknowledgement. A pending target shows a neutral marker, not the selection accent. Rows use `aria-disabled` while a mutation is in flight so keyboard focus is kept.

## Deferred scope

- Global OMP configuration/authentication management; Cockpit-driven provider sign-in flows (OAuth, passkeys) and glab/gh/tea token injection; remote browser access and multi-user authorization. Supervisor/worker launch with a per-process OMP extension is supported.
- Agent history and resumable conversations; a separate inbox popup; a Cockpit-owned settings screen.
- Provider-specific mutations and a complete cross-provider Forge/Issue Tracker/Wiki feature matrix. Existing Jira lookup/import and supported provider read slices are not a claim of a complete provider matrix.
- Unbounded previews, arbitrary user-entered shell execution, and raw socket forwarding remain outside the product contract. Executing Herdr-advertised configured commands is supported.
