Top recommendations

  1. NR-01 / 02 / 03 — Fix the attach picker layout (P1, CSS): content does not stack; the consequential transfer confirmation floats detached. Concept C1.
  2. NR-16 — Stop disguising adoption as “Comments” (P1, wording + icon label): an unadopted task’s comment button writes an id into todos.md. Same handler, honest label. C3.
  3. NR-43 — Make the shared problem slot in-flow (P1, layout only, S-only): the bottom overlay covers the bottom-anchored Save/Comment rows and, for unknown outcome, can hide the recovery controls it carries from view. No gate changes. C6.
  4. NR-12 / 13 — Conflict review hierarchy (P2, CSS): saved preview inherits the reading-column style; the overwrite button is the accent primary only on Scratchpad. C2.
  5. NR-22, 30, 31, 29 — Icon and affordance clarity (P2, CSS): Delete uses the same ✕ as Close; two identical “···” per card; plain-text jump chips; empty card action row. C3, C4.
  6. NR-15, 17, 18, 06 — State visibility and names (P2): board membership, stable toggle name, zero-result text, count meaning. C3, C7.
  7. NR-36 – 39 — Decisions hierarchy (P2): sort state announced, filter-outside context, decided vs recorded date, Replace discoverability. C5.
  8. NR-08 — Distinguish “close details” from “close Notes” (P2): same ✕ glyph stacked at narrow. C7.

Not in the polish set (need a separate decision first): tab-count basis, pre-adoption confirmation, draft markers on tabs, field-local validation, any focus transfer, draft-read warnings, hiding Doing/Done “+”, retained-draft default-open, broader unknown-outcome review, disabled-prop alignment, merged chrome, lane tracking. See Decisions.

Nonrecommendations — no feature expansion

No per-lane card creation · no task or decision delete control · no auto-save, auto-retry, auto-acknowledge or auto-adopt · no new shortcuts · no change to counts, sort, filter defaults or view-state persistence · no change to unknown-outcome incident scope · no new recovery UI · no merging Completed with Move · no modal conversion of the picker or confirmation · no rewrite of backend error messages · no change to Kanban drag thresholds, sensors or file-order semantics · no change to focus-return rules. Empty Kanban lanes already say “No cards.” and all lane “+” buttons intentionally focus the Backlog composer; this review does not claim otherwise.

Invariants every remedy is checked against: notes are ordinary local Markdown; UUID folder identity and Space association are separate; resolve once and pin UUID; canonical bytes ≠ drafts ≠ view state; CAS by byte revision, item revision or whole-document ref; adoption only on explicit mutation; source order is task/board order with no ranks; dirty text keeps its original revision until explicit review; unknown outcome is neither success nor failure and is never replayed; comments are durable and independent of board membership; decision history is additive with predecessor bytes untouched; bounded safe storage.
