# Migration / compatibility deletion inventory

Read-only inventory of `crates/`, `src-tauri/src`, `src/` (excluding generated protocol implementation), and `integrations/`. No source edits, builds, or tests were run. Line numbers describe the inspected checkout and must be refreshed before edits.

**Classification:** MIGRATION = exclusively old persisted/config/wire-format handling, removable under the owner's guarantee; CURRENT = current behavior or a format/value still emitted today, keep; UNSURE = a real boundary requiring care, not permission to delete. Counts are estimates of removable physical lines, including migration-specific tests, not promises or blanket file deletion instructions. Mixed tests must retain their current-contract assertions.

**Important current-format boundary:** removing upgrade code does not require changing current store schemas. Keep current schema/version validation. Several migration-named fields are still serialized into current strict (`deny_unknown_fields`) stores. Deleting those fields would reject the owner's *current* files too. Retain their current serialized shape unless changing current persisted formats is separately intended; deleting redundant `serde(default)` does not remove fields. Serde already treats a missing `Option<T>` as `None`, so deleting a default attribute on an Option is cleanup, not stricter decoding.
