# Quick ask: startup and multiline follow-up

## Outcome

Accept ordinary multiline questions without changing their text; choose a harness-specific interactive startup argument only where its parser contract supports it. Otherwise launch without the question and retain an explicit-send or manual-copy path. Never infer input readiness or consumption from launch/idle, replay an unknown effect, access credentials for verification, or register supervisor work.

Source review only, following commit `9dcc017`; no builds, tests, runtime experiments or product edits performed for this plan. Line references describe the inspected snapshot; Main reports implementation has since landed, so use this plan as an affected-contract checklist rather than overwriting concurrent work.

## Decisions (with rejected alternatives)

1. **Central, deterministic delivery policy, frozen per request.** For OMP/Pi/Claude/Codex, use exactly one positional question only when its first character is neither `@` nor `-` **and the unchanged string contains whitespace**. This is Main's conservative policy: whitespace excludes every exact one-word command token without a growing command denylist. Do not trim before classifying or split into words. All other positional inputs start without a question. Copilot/OpenCode retain their dedicated equals-form flags. Rejected: universal positional delivery, guessed `--`, per-character escaping, prepended spaces, wrappers or prompt files; these either alter input or do not defeat application parsing.
2. **Normal multiline is accepted as text, not terminal keystrokes.** Permit LF while retaining the 16,384-byte bound, nonblank rule and rejection of other existing unsafe controls (including CR/TAB/ESC/NUL/DEL/C1). Preserve the request's exact UTF-8 string; do not trim, normalize line endings or add a final newline. Enter inserts LF; Ctrl/Cmd+Enter starts. CRLF supplied through the API remains rejected rather than silently rewritten. Rejected: making all questions single-line or concatenating lines.
3. **Fallback has two safe forms.** For a startup-ineligible single-line question, preserve the current one-shot identity-gated `agent.prompt` only after an explicit user confirmation that the normal input prompt is visible and empty. Opening the tab is navigation, not confirmation. For startup-ineligible multiline, launch with no question and offer **Open tab + Copy question only**: do not expose Send, dispatch `agent.prompt`, or infer paste safety from idle. The core must reject an attempted Send too, not just disable the button. No automatic paste, Enter or replacement launch. Manual copying is never recorded as submission. Rejected: per-harness historical paste success as a live paste-mode guarantee.
4. **Truthful effect boundary and retained input.** Move into noncancellable delivery state before a startup-with-question launch; receipt means `initial_question_supplied`, never ready/consumed. Unknown launch with input or unknown prompt dispatch remains `outcome_unknown`, never replayed. No-question launch uncertainty can truthfully retain `not_sent`, but may have created a tab; do not claim no resource exists. Keep question text across supplied/submitted/failed/cancelled/unknown and ordinary closing; only explicit New question clears it. Status-only reconciliation may report the original operation's receipt, never trigger a second mutation.
5. **Keep scope and ownership.** Reuse the existing dedicated tab, sanitized argv launch, UUID fingerprint and identity gates. No supervisor/task/credential registration, credential-store inspection, auth copying, global settings, stdin plumbing, new readiness detector or automatic tab cleanup. Warn about prompt exposure in argv/layout metadata for every startup-eligible harness, not just the previous two.

## Open questions (options + recommendation)

- **Installed-version and downstream semantics:** source/docs support the candidate startup forms but do not establish every installed harness's trailing-LF behavior or normal special-command interpretation. Options: (a) claim consumption from creation; (b) retain supply-only receipts and record the missing acceptance evidence; (c) disable every startup path until authenticated probing. **Recommend (b)**. Owner checks should inspect available version-matched parser/source and unauthenticated real startup paths without credentials. If a parser contradicts a table row, use the already-defined no-question fallback for that harness; do not rewrite the payload. Auth-dependent consumption evidence remains explicitly unverified, not a reason to copy credentials.
- **Broader whitespace support:** tabs/CRLF could be admitted specifically on argv paths, but would complicate validation and terminal fallback. **Recommend LF-only in this change**; preserving/rejecting the supplied string is safer than silent normalization. No worker chooses a new normalization policy.

## Risks & verification

- **Wrong execution/identity:** option/file/subcommand interpretation can run something other than a question. S1's conservative conditional predicate and S2's exact single-argument tests cover routing; identity gates remain untouched. Installed Pi `--` contradiction is resolved above, not deferred.
- **Duplicate effects/concurrency:** startup delivery occurs during creation, not later prompt dispatch. S2 preserves the noncancellable boundary and unknown terminal result; S3 never turns transport uncertainty into a new start or send. Exercise send/cancel races and duplicate UUID replay.
- **Input loss:** LF acceptance alone is insufficient if success clears the draft or payloads are trimmed. S2 checks exact bytes through serialization/argv; S3 retains them after receipts and navigation. Downstream harness transformations are not represented as Cockpit byte-preservation proof.
- **Credential/authority leakage:** preserve the current allowlist; verification reads no auth/config credential exports and binds no real credential directories into fixtures. Source review is not a claim that inherited HOME prevents a launched agent from using its normal credentials.
- **False readiness/manual recovery:** idle, Open tab and clipboard success prove neither empty prompt nor submission. S3 requires explicit confirmation for single-line send and labels multiline copy-only honestly. No pane is closed or draft overwritten by recovery.
- **Review boundary:** one high-severity review by Main for duplicate-effect/identity/security changes, then targeted owner checks. This document reports only source inspection; every runtime/build/test acceptance above is pending owner evidence.
