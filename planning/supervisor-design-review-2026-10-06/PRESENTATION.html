Supervisor — design review of the atlas

Recommendations only. The Supervisor should read as an observational task board: the supervising agent manages grants, review and acceptance; the user sees what needs a decision, what needs recovery, and what finished. Operator controls stay available but secondary. Full findings, tradeoffs, keyboard behavior and the 58-ID coverage matrix are in DESIGN.md.

  • Evidence-derived schematic redrawn from current CSS/TSX and atlas IDs; not a screenshot
  • Concept proposed, not implemented
  • Illustrative values every name, time and count is example data
  • Local demo working prototype on illustrative data (section 1b); no product, terminal or network action

Chips that look like buttons in the schematic and concept frames are inert text. The navigation links, the disclosure triangles and the section 1b local demo respond; the demo changes nothing outside this page.

Authority invariants preserved

Nothing above changes who may act, which revision fences a write, or what counts as proof. The full list (A1–A10) is in DESIGN.md §1.1.

  • Task source. Canonical Markdown stays the only store; writes keep exact revisions (A1).
  • Supervisor authorizes. Prepare/Execute by the bound supervisor; operator override stays explicit, exact-plan, same-user-policy copy kept (A2).
  • Acceptance. Explicit successful Result + current exact task revision; runtime Done is not acceptance (A3).
  • Provenance. Reported ≠ observed ≠ receipt; unavailable ≠ absent; “unobserved” stays (A4).
  • Close ≠ kill. Descendants and resources remain; Check status is read-only; Restart guarded (A5).
  • Unknown writes. Drafts and operation identity retained; no blind replay (A6).
  • Subagents. No terminal; stored ≠ applied ≠ completed; not the parent’s Result (A7).
  • Focus. Selection ≠ DOM focus ≠ Herdr focus; terminal hand-off explicit and fenced. The Tasks · Graph switch, selection and Show in Graph / Show in Tasks never change Herdr focus (A8).
  • Intentional removals. No task composer, no “Other agents”, no empty-state paragraph reintroduced (A9).

Limitations

  • No browser, build, test, native or live OMP/Herdr run was performed for the original review; its frames are schematics, not screenshots. Revision 2026-10-07 adds a static Graph figure and a local demo; the author did not run them in a browser, and this page claims no browser verification.
  • Atlas screenshots are historical (composer, “Other agents” and empty-state paragraph present); only layout behavior is taken from them. Populated, attention, detail and dialog images are synthetic component states; live images cover empty workarea, Activity/Diagnostics, narrow Diagnostics and Start options only.
  • The ≈3.4 : 1 contrast figure for dimmed muted text is arithmetic from CSS tokens, not a browser measurement.
  • All names, times, counts and statuses in the frames are illustrative; no metrics were measured.
  • Schematic and concept frames are inert; only the navigation links, disclosure triangles and the section 1b local demo respond. The demo uses illustrative data and performs no product, terminal, Herdr, network or storage action. Hosts that strip scripts show the static figures but not a working demo.
