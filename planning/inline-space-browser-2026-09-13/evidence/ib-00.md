## Unified CLI and CDP ownership

The disposable named Playwright CLI session was opened with one persistent profile and a generated config containing:

```json
{
  "browser": {
    "launchOptions": {
      "args": [
        "--remote-debugging-address=127.0.0.1",
        "--remote-debugging-port=4321"
      ]
    }
  }
}
```

The resulting Chrome command line exposed both the CLI's `--remote-debugging-pipe` and the private loopback `--remote-debugging-port=4321`. `GET /json/version` reported Chrome 153.0.8010.36, protocol 1.3, and a websocket debugger URL. A separately launched `playwright-core` CDP client attached to that endpoint without launching or closing Chromium, navigated the existing CLI page, set `document.title = "CDP coexistence"`, set a DOM marker, and received a JPEG `Page.startScreencast` frame:

```json
{"url":"http://127.0.0.1:4381/index.html","title":"CDP coexistence","marker":"same-browser","frameBytes":51755,"frameMetadata":{"offsetTop":0,"pageScaleFactor":1,"deviceWidth":1280,"deviceHeight":720,"scrollOffsetX":0,"scrollOffsetY":0,"timestamp":1789277418.391246}}
```

The ordinary CLI then read the same mutation from the same page:

```json
{"title":"CDP coexistence","marker":"same-browser"}
```

This proves the required launch seam: the helper can attach to the browser already owned by the named CLI session. It does not authorize the helper to launch a browser or become lifecycle owner.

## Gate result

IB-00 launch coexistence, target/document identity, binary web/native surface, geometry, IME, clipboard, and visible blocker capabilities are proven for the disposable Linux environment. Production work must preserve these properties with a versioned envelope, verified incarnation/profile binding, owner-issued view credentials, explicit capability events, and no second-browser or extension fallback.
