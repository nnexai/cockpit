# Supervisor surface inventory

This is the current UI/source map and coverage-source inventory, not a record of checks run by this documentation update. [DECISIONS](../DECISIONS.md) owns normative authority rules; [CODE_GUIDE](../CODE_GUIDE.md) maps request flows and implementation owners. Earlier provenance, shipped defects and runtime observations live in the [verification log](verification-log.md) and [decision archive](../archive/decisions-log.md).

## Product surfaces

Tasks is the default view. Graph shows worker hierarchy; Dependencies shows canonical task prerequisites. Give work in the supervisor terminal; the dashboard explains progress and exposes decisions and guarded recovery.

### Current UI contract and source map

- **Tasks and attention:** Tasks opens by default. The read-only lanes show Queued, Preparing, Ready, Working, Review and a collapsed Done disclosure; `setup` and `accepted` remain the underlying core lane values. Cards show task identity, worker/subagent context, separate reported/observed provenance and literal failed-report text. Ordinary successful report bodies stay in details. Attention and Space filters dim rather than remove work. A compact Agents strip is available on wide, non-short Tasks layouts; Graph is a visible peer view, not an always-mounted preview.
- **One attention model:** [`attention.ts`](../src/app/supervisor/attention.ts) consumes authoritative core attention plus explicit local conditions. Root NeedsInput is **Decide**; blocked/unknown/exited-without-report recovery is **Recover**; idle/unread/changed-plan and intent/document notices are **Notice**. Routine Prepare, Execute, Result acceptance and worker NeedsInput stay supervisor-owned and do not inflate user counters. Causes are grouped by tier and subject, retain provenance and real core age, and drive queue rows, counters, root summaries, card/node badges and the attention filter together. Local-only rows do not invent timestamps.
- **Answer receipts:** Root Needs-you answers retain the exact current question link and delivery identity across uncertain outcomes; a newer question gets a separate scoped draft. Shared root summaries, worker cards and Overview details consume authoritative `snapshot.questions`: unresolved questions wait for the supervisor; Stored/Woken/Read Answers show **Answer sent · not yet processed**; Acked Answers show **Answer acknowledged · awaiting report**. Details show sender, delivery stage and timestamps, with **A receipt, not proof that work resumed** until a fresh main report replaces the request. Delivered/acknowledged questions stop asking the user to answer again, without changing lifecycle, grants or acceptance. Worker questions remain supervisor-owned; recovery/offline conditions keep priority.
- **Queue:** [`SupervisorAttention.tsx`](../src/app/supervisor/SupervisorAttention.tsx) renders controlled disclosures and roving summary buttons. Counters explicitly focus the requested tier or open the attention overlay; polling does not move field focus. The inline queue is height-bounded and scrollable, including oversized expanded rows; its More indicator counts partially hidden rows. Narrow workareas and short windows use an overlay instead of squeezing the workarea.
- **Topology and Graph:** [`topology.ts`](../src/app/supervisor/topology.ts) builds Supervisor → canonical task → assigned worker relationships from `current_run_id` and explicit delegation/subagent parentage, never labels, Space location or a worker's `task_id` alone. Unassigned and nested workers remain represented; closed runs and completed tasks are omitted from Graph with a completed-task count. [`graphLayout.ts`](../src/app/supervisor/graphLayout.ts) deterministically lays out fixed 240×48 nodes with 32px column gaps and 56px row pitch, handling missing parents, cycles and deep chains iteratively. [`SupervisorGraph.tsx`](../src/app/supervisor/SupervisorGraph.tsx) owns the single graph scrollport, sticky column headings, named node/status/provenance anatomy, chain highlighting and optional internal subagents. Filters leave dimmed nodes keyboard-reachable.
- **Review-first details:** [`SupervisorActions.tsx`](../src/app/supervisor/SupervisorActions.tsx) presents Overview / Activity / Actions. Overview puts state, provenance, explicit Result and progress before the relationship path and task description. The path and **Show in Tasks / Show in Graph** are local navigation only. Operator intervention is collapsed by default, except an armed override or acceptance conflict; opening it grants no authority. Acceptance still requires explicit successful Result, current canonical assignment and exact task revision; plan changes disarm an override. Recovery precedes guarded restart. Unknown deliveries retain text and operation identity, with no automatic retry or implied success.
- **Responsive layout and reveal:** [`useSupervisorLayout.ts`](../src/app/supervisor/useSupervisorLayout.ts) is the shared measurement model: workarea widths below 720px stack Tasks and use overlays; below 480px is compact; window heights at or below 600px use the attention overlay. Details use a resizable side panel on wide layouts, a resizable Graph sheet on narrow workareas at least 560px high, and an overlay otherwise. [`PanelSplitter.tsx`](../src/app/supervisor/PanelSplitter.tsx) supports pointer/keyboard resizing and reset. [`reveal.ts`](../src/app/supervisor/reveal.ts) minimally scrolls only the owning client scrollport, accounting for sticky headings and a Graph sheet. A visible node click preserves offsets. Tasks/Graph and lane offsets, disclosures, selection, filters, panel preferences and drafts are root-scoped in [`useSupervisorDrafts.ts`](../src/app/supervisor/useSupervisorDrafts.ts); restoration does not authorize mutations or focus a terminal.
- **Activity, diagnostics and archive:** [`SupervisorActivity.tsx`](../src/app/supervisor/SupervisorActivity.tsx) derives readable messages, grants and annotations grouped by local day, with accurate actor attribution, stale-evidence marks and local task/run links. Bootstrap pointers and technical acceptance receipts have readable summaries; exact plans, native sessions and delivery records remain in Diagnostics. Closed tracking shows per-root task-count loading/unavailable states and retained open descendants. [`useArchiveCounts.ts`](../src/app/supervisor/useArchiveCounts.ts) fetches archive counts only while open, with at most four concurrent snapshots, session/root identity and disclosure-generation fences. Its date is **Updated**, not an invented closure time.
- **Authority and intentional removals:** Selecting, revealing, filtering or switching views never submits work, grants permission or requests Herdr focus. Only explicit **Open terminal** uses the existing fresh, identity-fenced App navigation and focus acknowledgment. Canonical Markdown/CAS and bound-session authority are unchanged. The bottom Task composer/resize handle, assignment notice, Other agents filter, unmanaged overview, no-agent explanatory paragraph and Start agent focus tooltip remain removed. Unmanaged agents stay in the sidebar. Give work in the supervisor terminal; hide/return, failed delivery, offline transitions and explicit recovery retain relevant drafts and unknown-operation identity.
- **Prerequisites and follow-ups:** [`SupervisorDependencies.tsx`](../src/app/supervisor/SupervisorDependencies.tsx), [`dependencies.ts`](../src/app/supervisor/dependencies.ts) and [`dependencyLayout.ts`](../src/app/supervisor/dependencyLayout.ts) keep canonical task dependencies separate from the worker hierarchy and nested steps. Accepted prerequisites remain visible, independent work remains runnable, and missing/invalid/cyclic prerequisites show affected-task reasons. Follow-up provenance is nonblocking, immutable and visible even for a removed source. Creation optionally waits on that source; scoped prerequisite edits retain drafts and task/document revisions.
- **Hierarchical steps:** [`SupervisorSteps.tsx`](../src/app/supervisor/SupervisorSteps.tsx) renders actual native checkboxes, leaf-derived mixed branch state/progress, local tree keyboard navigation, stable UUID rename/reparent/reorder/remove and explicit descendant previews. Numeric overflow remains readable with safe shrink/check actions, while malformed structure is read-only with unavailable progress. Destination ancestors reveal after a move, and same-UUID focus waits for the saved task revision/rendered destination without stealing later navigation. Removing a subtree chooses a surviving actual row, not a temporarily hidden descendant.
- **Protected task editing and uncertainty:** task-description editing preserves reserved metadata and checklist bytes; Working content belongs to the current exactly executed worker and real live native task child, not the dashboard/root manager. Prerequisite changes have a separate strict-removal-only open-attempt API boundary. Scoped editor drafts and unknown operations keep original task/root, UUID, payload and revisions; polling, navigation and failed delivery cannot implicitly clear or replay them. Explicit saved-state resolution is required.
