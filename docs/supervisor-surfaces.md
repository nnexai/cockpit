# Supervisor surface inventory

This is the current UI/source map and coverage-source inventory, not a record of checks run by this documentation update. [DECISIONS](../DECISIONS.md) owns normative authority rules; [CODE_GUIDE](../CODE_GUIDE.md) maps request flows and implementation owners. Earlier provenance, shipped defects and runtime observations live in the [verification log](verification-log.md) and [decision archive](../archive/decisions-log.md).

## Product surfaces

Tasks is the default view. Graph shows worker hierarchy; Dependencies shows canonical task prerequisites. Give work in the supervisor terminal; the dashboard is observational, with genuine decisions, guarded recovery and separate source Outcome, Integration and Cleanup.

### Current UI contract and source map

- **Tasks and attention:** Tasks opens by default. Read-only lanes show Queued, Starting, Working, Review and a collapsed Done disclosure (`accepted` in core). Initialized is diagnostic only. Cards show task identity, canonical assigned conversation/harness or Unassigned/ownership pending, reported/observed provenance and literal failed-report text. Pending launch and process labels do not invent an owner. Latest progress stays quiet; ordinary report bodies remain in details. Attention and Space filters dim rather than remove work. A compact Agents strip is available on wide, non-short Tasks layouts; Graph is a visible peer view.
- **One attention model:** [`attention.ts`](../src/app/supervisor/attention.ts) combines core attention and explicit local conditions. Genuine unresolved root questions are **Decide**, blocked/unknown recovery is **Recover**, and diagnostic/document notices are **Notice**. Routine worker implementation, questions, source review and integration coordination remain liaison-owned rather than user approvals. Causes retain provenance and real core age across queue rows, counters, summaries and badges; local-only rows do not invent timestamps.
- **Answer receipts:** Answers retain the exact current question link and delivery identity across uncertain outcomes; a newer question gets a separate scoped draft. Delivery and explicit inbox ACK describe durable capture, not an Answer, model processing or resumed work. Details retain sender, delivery stage and timestamps. Only an explicit question-linked Answer addresses NeedsInput; fresh runtime evidence is separate. Worker questions remain liaison-owned, while recovery/offline conditions keep priority.
- **Queue:** [`SupervisorAttention.tsx`](../src/app/supervisor/SupervisorAttention.tsx) renders controlled disclosures and roving summary buttons. Counters explicitly focus the requested tier or open the attention overlay; polling does not move field focus. The inline queue is height-bounded and scrollable, including oversized expanded rows; its More indicator counts partially hidden rows. Narrow workareas and short windows use an overlay instead of squeezing the workarea.
- **Topology and Graph:** [`topology.ts`](../src/app/supervisor/topology.ts) builds Supervisor → canonical task → assigned worker relationships from `task_ownership` owner records and explicit Cockpit run parentage, never labels, Space location, pending authorization or a worker's `task_id` alone. Unassigned and nested workers remain represented; historical workers do not masquerade as current owners. Closed runs and completed tasks are omitted from Graph with a completed-task count. [`graphLayout.ts`](../src/app/supervisor/graphLayout.ts) deterministically lays out fixed 240×48 nodes with 32px column gaps and 56px row pitch, handling missing parents, cycles and deep chains iteratively. [`SupervisorGraph.tsx`](../src/app/supervisor/SupervisorGraph.tsx) owns the single graph scrollport, sticky column headings, named node/status/provenance anatomy and chain highlighting. Native-child nodes, counts and controls are absent. Filters leave dimmed nodes keyboard-reachable.
- **Review-first details:** [`SupervisorActions.tsx`](../src/app/supervisor/SupervisorActions.tsx) presents Overview / Activity / Actions. Overview puts state, assigned conversation (full selectable harness/session ID), provenance, source Outcome, Integration, Cleanup and progress before the relationship path and task description. Reports from a previous assignment remain readable and explicitly attributed, not relabeled as a replacement's Result. **Show in Tasks / Show in Graph** is local navigation only. Source acceptance requires a succeeded Result with SourceOutput bound to the exact result ID and current canonical task revision, not the launch-time task revision; target integration and resource removal are separate facts. Recovery tries reattachment first; unknown deliveries keep text and operation identity with no automatic replay or implied success.
- **Responsive layout and reveal:** [`useSupervisorLayout.ts`](../src/app/supervisor/useSupervisorLayout.ts) is the shared measurement model: workarea widths below 720px stack Tasks and use overlays; below 480px is compact; window heights at or below 600px use the attention overlay. Details use a resizable side panel on wide layouts, a resizable Graph sheet on narrow workareas at least 560px high, and an overlay otherwise. [`PanelSplitter.tsx`](../src/app/supervisor/PanelSplitter.tsx) supports pointer/keyboard resizing and reset. [`reveal.ts`](../src/app/supervisor/reveal.ts) minimally scrolls only the owning client scrollport, accounting for sticky headings and a Graph sheet. A visible node click preserves offsets. Tasks/Graph and lane offsets, disclosures, selection, filters, panel preferences and drafts are root-scoped in [`useSupervisorDrafts.ts`](../src/app/supervisor/useSupervisorDrafts.ts); restoration does not authorize mutations or focus a terminal.
- **Activity, diagnostics and archive:** [`SupervisorActivity.tsx`](../src/app/supervisor/SupervisorActivity.tsx) presents readable messages, operation receipts and annotations grouped by local day with actor attribution, stale-evidence marks and local task/run links. Physical attachment, assignment generation, source and delivery records remain in Diagnostics. Closed tracking retains open descendants and truthful per-root task-count loading/unavailable states. [`useArchiveCounts.ts`](../src/app/supervisor/useArchiveCounts.ts) uses bounded concurrent snapshots and session/root/disclosure fences; **Updated** is not an invented closure time.
- **Authority and navigation:** Selecting, revealing, filtering or switching views never submits work or requests Herdr focus. Only explicit **Open terminal** uses fresh physical identity-fenced App navigation and focus acknowledgement; a conversation ID is not a terminal locator. Private role credentials, registered conversation and pinned assignment generation govern semantic mutations, not focus or labels. Give work in the supervisor terminal; hide/return, offline transitions and recovery preserve relevant drafts and unknown-operation identity. Ordinary local worker tools remain autonomous within scoped work; this is not an OS sandbox.
- **Semantic request availability:** Durable answers and supervisor requests (including unassign/pending cancellation) require an active root with registered `attachment.conversation` and a current Cockpit connection. They do not require `actual_agent`, a harness detector or fresh Herdr physical observation; a registered non-OMP conversation remains eligible without detector support. This does not relax credential/owner/generation or exact-question fences. Open terminal, restart, prompt submission and cleanup remain separately physical-evidence-gated.
- **Unclassified harness observation:** A physically present owned root/worker with a registered conversation and `actual_agent = false` due only to missing harness classification is labeled **Registered conversation**, with **Herdr cannot classify this harness** as separate observation—not fabricated native running or a detector-only Resume/Recover condition. Actual absence, endpoint contradiction, blocked/error evidence and physical-navigation gates remain effective.
- **Prerequisites and follow-ups:** [`SupervisorDependencies.tsx`](../src/app/supervisor/SupervisorDependencies.tsx), [`dependencies.ts`](../src/app/supervisor/dependencies.ts) and [`dependencyLayout.ts`](../src/app/supervisor/dependencyLayout.ts) keep canonical task dependencies separate from the worker hierarchy and nested steps. Accepted prerequisites remain visible, independent work remains runnable, and missing/invalid/cyclic prerequisites show affected-task reasons. Follow-up provenance is nonblocking, immutable and visible even for a removed source. Creation optionally waits on that source; scoped prerequisite edits retain drafts and task/document revisions.
- **Hierarchical steps:** [`SupervisorSteps.tsx`](../src/app/supervisor/SupervisorSteps.tsx) renders actual native checkboxes, leaf-derived mixed branch state/progress, local tree keyboard navigation, stable UUID rename/reparent/reorder/remove and explicit descendant previews. Numeric overflow remains readable with safe shrink/check actions, while malformed structure is read-only with unavailable progress. Destination ancestors reveal after a move, and same-UUID focus waits for the saved task revision/rendered destination without stealing later navigation. Removing a subtree chooses a surviving actual row, not a temporarily hidden descendant.
- **Protected task editing and uncertainty:** Description editing preserves reserved metadata and checklist bytes. A Working scope update fences both canonical task and document revisions and durably instructs the same current worker; worker self-refinement sends no self-message. Worker writes validate current conversation ownership and pinned generation. Active prerequisite changes cannot insert unmet dependencies under a writer. Scoped drafts and unknown operations retain original task/root, UUID, payload and revisions; polling, navigation and failed delivery cannot clear or replay them. Explicit saved-state resolution is required.
- **Request unassign/pending cancellation:** Existing Actions → Advanced sends a durable request to the verified owning supervisor, pinned to root/task/generation and current owner run/conversation or authorized pending attempt. It is not a direct operator ownership mutation. Stored/ACKed requests do not change owner metadata; only canonical newer-generation unassignment/revocation confirms completion. A claim/replacement that wins the race invalidates the old request, never retargets it. Confirmation states that reports/history/files/Spaces stay and stopping or checkout release is not implied. Previous-worker stop-not-proven evidence remains separate, protecting the old checkout even when safe disjoint replacement exists. Task drafts remain task-local; worker feedback stays with its original assignment and is never transferred.
- **Configured harness startup and inbox:** Existing Name/Location/Space start flow uses file-backed literal harness launch settings; no new picker/settings surface or mandatory extension. `run context`/`run register` binds a capability to the actual resumable conversation; worker claim is atomic. CLI `inbox wait`, pull/capture and explicit ACK are baseline. Default-off regular counts-only prompt hints submit text plus Enter to an identity-checked owned pane, defer busy/unready targets and retain unknown effects; enabling hints does not promise unknown-draft safety. Configuration errors remain inline and preserve start drafts.
