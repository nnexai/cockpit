# Supervisor surface inventory

This is the current UI/source map and review inventory, not a record of checks run by this documentation update. [DECISIONS](../DECISIONS.md) owns authority rules; [CODE_GUIDE](../CODE_GUIDE.md) maps request flows. Historical observations remain in the [verification log](verification-log.md) and [decision archive](../archive/decisions-log.md).

## Product surfaces

The liaison's real terminal is the primary conversation. A compact read-only rail summarizes open tasks; an optional fullscreen Overview provides Board and Graph. Human decisions happen in the liaison conversation, not a separate approval or worker-answer interface.

Batch completion leaves the liaison Active for later work on the same project root; worker `run done` and source cleanup do not retire the liaison. Root completion is conversational, not another operational button.

### Current UI contract and source map

- **Conversation and startup:** [`useLiaison.ts`](../src/app/supervisor/useLiaison.ts) finds the selected Space's project root, reuses/resumes it and navigates to its exact real pane. Start does not attach a second terminal or invent a synthetic Herdr resource. The ordinary terminal control/focus rules remain authoritative.
- **Quiet liaison labels:** [`useLiaison.ts`](../src/app/supervisor/useLiaison.ts) supplies exact root/tab/pane identity. [`WorkbenchContent.tsx`](../src/app/shell/WorkbenchContent.tsx) passes `liaisonTab` to [`TabStrip.tsx`](../src/app/shell/TabStrip.tsx); **Supervisor** appears only for matching recorded tab ID and raw launch-tag label. [`WorkbenchCanvas.tsx`](../src/app/shell/WorkbenchCanvas.tsx) passes **Liaison** through [`LeafHost.tsx`](../src/app/layout/LeafHost.tsx) only for the exact root pane/raw launch-tag title. Custom labels stay unchanged; aliases never mutate IDs, durable tags, focus/drag/rename payloads or membership proof.
- **Compact rail:** [`SupervisorTasks.tsx`](../src/app/supervisor/SupervisorTasks.tsx) renders the task rail attached to the actual liaison [`TerminalLeaf`](../src/app/layout/TerminalLeaf.tsx) through [`LeafHost`](../src/app/layout/LeafHost.tsx). It is hidden when there are no open tasks. Tasks remain distinct from replaceable attempts; Blocked/Ready/Working/Review/Done are canonical task projections, while Starting is attempt status.
- **Fullscreen Overview:** [`SupervisorView.tsx`](../src/app/supervisor/SupervisorView.tsx) offers read-only Board and Graph. Conversation and Escape return to the liaison. [`useWorkarea.ts`](../src/app/shell/useWorkarea.ts) owns the `overview` workarea, not task-editing or startup-modal tokens. Merely observing tasks does not submit work or focus a worker.
- **Board and prerequisite graph:** Board shows five task columns. [`SupervisorGraph.tsx`](../src/app/supervisor/SupervisorGraph.tsx), [`dependencies.ts`](../src/app/supervisor/dependencies.ts) and [`dependencyLayout.ts`](../src/app/supervisor/dependencyLayout.ts) render the canonical prerequisite DAG, not a run/agent hierarchy. Canonical dependencies and stable tasks do not disappear when an execution attempt is replaced.
- **Actual dependency inputs:** Canonical checked prerequisites and accepted status are not a guarantee that a same-repository Code output is in the next checkout. Scheduling freezes/validates actual predecessor commits or holds work queued with a concrete liaison cause. NonCode output references remain accessible and preserved. Graph/board remain observational; no per-step approval or operational retry UI is added.
- **Quiet human-wait hint:** [`useLiaison.ts`](../src/app/supervisor/useLiaison.ts) checks the nonclosed root's question (`run_id === root.run_id`) for `QuestionStatus.receipt.status === "unresolved"`, not historical `last_report`. Core `current_question(messages)` preserves questions across Progress. Exact actual-human `run answer` capture clears unresolved state while keeping NeedsInput history; stale/replayed answers cannot clear newer questions. The hint appears in rail/Overview, [`TabStrip`](../src/app/shell/TabStrip.tsx) and [`WorkbenchContent`](../src/app/shell/WorkbenchContent.tsx)'s polite live region. Worker questions and cleanup/recovery remain liaison-owned.
- **No dead operational dashboard:** Activity, Diagnostics, archive, attention queues/counters, worker Answer/Retry buttons, task/step editors and decision forms are removed. Durable records and CLI coordination remain available without duplicating them as noisy screens. Legitimate unrelated project teardown/recovery surfaces remain.
- **Semantic and physical authority:** Active private attempt credentials, root/run/epoch and task generation authorize coordination. Actual conversation metadata is optional and validated when supplied; names, process labels and UI selection grant nothing. Terminal navigation/effects and cleanup still require their exact physical proofs. Atomic isolated replacement preserves old dirty/unmerged work and claims rather than relabeling them as successor output.
- **Quiet scoped observation:** [`useSupervisor.ts`](../src/app/supervisor/useSupervisor.ts) observes the selected session/root and task token. Directory notifications cover cross-process commits and external Markdown edits, including atomic replacement; unchanged wait deadlines renew without refreshing full snapshots. CLI inbox pending waits read only durable metadata, not bodies, task boards or live Herdr. Watch/backend failures are explicit and retried on the next wait rather than permanently losing wakeups. Cleanup registers Git common-directory watches with the same service; only packed-refs/loose refs trigger wakes, not objects/index/read/lock churn. Retired resources remove watches; directory replacement/backend errors cause registration to rebuild.
- **Output publication wakes:** The same watcher covers the attempts root and immediate UUID output directories nonrecursively. Output-entry create/remove/rename wakes empty-only cleanup after durable publication/move; reads, content changes and nested-tree activity are ignored. No timer or UI retry is required, and watch registration grants no deletion authority.
- **Launch and delivery honesty:** Literal initial prompts and optional per-launch OMP hooks remove required skill/identity/ACK model turns. Credential-scoped `inbox next` captures messages internally; capture is not model processing or an Answer. Launch acknowledgement, observed physical readiness, credential activation and first model response are separate observations. Desired launch/communication targets are not measured acceptance here.
- **Safe cleanup and recovery:** Relevant durable/pane/ref events trigger idempotent reevaluation. Accepted idle owned-pane retirement needs exact fresh proof. Dirty, unmerged, borrowed, unknown and unproven old writers remain protected; concrete blockers are deduplicated to the liaison. Proven ordinary integration may reuse an exact already verified target receipt; adapted integration retains actual passed-check IntegrationRecord evidence. No timer, UI retry or acceptance alone manufactures safe disposal.
- **Borrowed-checkout holds still reach the liaison:** A scope hold with no eligible owned filesystem/Space row sends an existing Dispatcher Observation only for the exact current run/epoch and pending owned claim/holder with a nonclosed root. Durable run/epoch/cause dedup survives capture/restart; a different concrete cause may produce one new notice. No pending claim means no notice. This meaningful boundary is not quiet Progress, fabricated ownership/resource data or a new UI; drain/release/foreign-consumer gates are unchanged.
- **Pane-close capability hold:** Primary-Git automatic retirement remains Kept with `foreign_space_group_close_risk`. Linked/non-Git permits only exact pane close, never workspace close, under normal proof gates. This concrete liaison hold is not a UI retry or permission to affect foreign grouped Spaces.
- **Fresh absence proof:** Owned Space absence matches exact endpoint/session/placement, then genuine recorded/fresh legacy boot or proved NativeProcessIdentity Some pair; conflicting both-present boot/peer evidence refuses even if the other matches. Same-FD own-UID PID/start/kernel/still-running proof is immutable in retirement/location. Foreign Git census independently requires fresh complete peer, not historical run identity. None/opaque/missing never proves absence; no hash/backfill/global endpoint change or host-ID startup gate is introduced.
- **Contained same-boot cleanup:** Accepted-worker stop needs current exact accepted/retired output proof and no Held/Queued holder; code needs clean integrated HEAD, NonCode exact Result/source/NotApplicable/artifact attestations/passed checks. Separate committed WorkerReplace authority may retire the exact old idle Superseded pane and stop only its verified old scope, never old files. Foreign cwd consumers block later claim release/deletion proof, not isolated scope stop. Old data remains Kept even after release; roots/cancelled/arbitrary scopes never stop. Escaped writers need separate consumer proof; accepted cleanup predicates remain unchanged.
- **Directory replacement/output preservation:** Live/unknown Directory writers can be replaced in private no-copy attempt directories while original project/context/source and old resources/claims remain unchanged. `COCKPIT_SOURCE_PATH` is read-only by instruction, not a sandbox. Accepted/NotApplicable output is not deletion authority: only exact accepted retired drained EMPTY owned attempts can retire. Nonempty deliverables stay `outputs_kept` until durable publication/move; cancelled/superseded/failed attempts remain preserved. No new operational UI.

## Non-visual integration

- Shared typed operations and decoding: `src/client/CockpitClient.ts`, `src/client/operations.ts`, `src/client/orchestrationProtocol.ts`, generated `src/protocol/generated/v1.ts`; shared host registry/handlers in `crates/cockpit-host/src/transport/`.
- Canonical task/stage/dependency authority and schema-4 schedules/attempts: `crates/cockpit-core/src/orchestration.rs`, `orchestration/tasks_md.rs`, `dependencies.rs`, `steps.rs`, `projection.rs`, `credentials.rs`, `mutate/runs.rs`, `mutate/ownership.rs`; protocol `crates/cockpit-protocol/src/orchestration.rs`.
- Runtime scheduling, literal launch, notifications and pending deadlines: `crates/cockpit-host/src/orchestration_runtime.rs`, core `orchestration/dispatch.rs`, `crates/cockpit-herdr/src/cli/orchestration.rs`; [configuration](configuration.md).
- Harness-neutral CLI and durable internal capture: `crates/cockpit-host/src/cli_orchestration/`, core `orchestration/messages/inbox.rs`. Herdr interactions, CLI and optional hooks are adapter choices; no OMP auth/session-file product dependency. The first optional hook is `integrations/omp-hook/cockpit-hook.ts`, embedded by core `orchestration/omp_hook.rs`; public API queueing never implies a model answer.
- Integration, cleanup and retirement: core `orchestration/mutate/integration.rs`, `cleanup.rs`, `retire.rs`, `retirement.rs`. Existing `resource_queue.rs` continues build arbitration; replacement does not release unknown old consumers.
- Harness-neutral process-scope launch/capture/observe/exact stop: `crates/cockpit-core/src/process_scope.rs`, literal helper `crates/cockpit-host/src/bin/cockpit/contain.rs`; domain receipt/seal/release proof in protocol `orchestration.rs` and core `orchestration/{store,claims,project_identity}.rs`. No additional UI.
- Placement-gated generic execution: `crates/cockpit-host/src/bin/cockpit/agent_exec.rs`; private receipt-fenced per-incarnation FIFO delays every harness/hook until final placement IDs, with one 20-second deadline and no credential/authentication bypass. No new UI.
- Single-terminal filesystem preparation/context binding: `crates/cockpit-core/src/projects/prepare.rs` (`prepare_owned_checkout`, `prepare_directory`, `bind_moved_space`) uses the existing operation journal and explicit primary Library service, without creating setup/context shells. Exact new-Space receipts and saved source Library selections preserve context, focus and user setup semantics.
- Worker resume binding: `crates/cockpit-core/src/projects/resume.rs` (`bind_resumed_space`) records only a new Space around the verified existing checkout when the retained Space is absent; retained Space stays in place. Original setup/FS creator or legitimate borrowed None, old receipts, commits and dirty files are preserved; root recovery is unchanged.
- Private Directory attempt preparation: `crates/cockpit-core/src/projects/attempts.rs` (`prepare_owned_attempt_directory`), exact four-field creation identity and existing journal. No machine-ID startup dependency, manifest, source copies or Git; retained receipts preserve output files across restart.
- Sealed accepted-worker scope cleanup: `orchestration/cleanup/scopes.rs` (`cleanup_worker_scopes`) and `project_identity.rs` (`checkout_consumers_clear`). Dirty/nonaccepted HEAD, resource admission and unavailable containment preserve Git/scratch and report concrete liaison blockers (`scope_dirty_checkout`, `scope_unaccepted_commits`, `scope_resource_admission`, `containment_unproven`).

## Review inventory

Select affected source checks and a real disposable affected-path browser/native run after implementation is stable. Review hidden-empty rail, narrow/wide resize, Board/Graph, Conversation/Escape return, no duplicate attachment, root-only waiting hint and removal of obsolete operational forms. Separately exercise dependency release/parallelism, replacement while the old writer remains live, internal inbox capture, safe cleanup refusal and liaison recovery. Record launch acknowledgement, physical readiness, credential activation and model-response timestamps separately.

For named Code DAG A → B, accept A before its output is materialized: B must stay queued. Afterward verify B's actual frozen checkout contains A's original accepted commits/output or exact validated Integrated target/mapped commits/output with passed target checks—not merely a lane/counter transition. Exercise explicit-base and adapted-integration proof, changed HEAD after checking, exact Result/task/source/integration fences, unrelated/manual edges and preserved accessible NonCode references.

Same-boot scope acceptance requires a real disposable non-OMP contained launch, accepted clean/integrated worker cleanup including orphaned/clean-environment children, dirty/pending-integration refusal, natural superseded drain, off/unsupported fallback and interrupted seal/release recovery. Verify only exact receipt-owned fixture units are affected, old scopes are not retrofitted, and no-force worktree removal succeeds safely. These are required scenarios, not observed results.

Directory acceptance must retain an actual non-code artifact before durable publication/move, keep the live/unknown old source and claims unchanged, and remove only the exact drained accepted owned directory after it is empty. Exercise NotApplicable without output loss, `outputs_kept` for nonempty attempts, no borrowed-source deletion and retention of superseded/cancelled/failed attempts. This is a required safety recipe, not a test receipt.

Replacement retirement should close only the exact old idle pane and stop only its exact owned scope while preserving every old dirty/output byte and the successor. Exercise busy/resource/descendant and invalid-authority refusal; with a foreign cwd consumer, isolated stop may complete but claim release remains blocked/Kept. Missing scope receipts permit no invented drain, and repeated stop requires fresh same-invocation Populated proof. Measure the under-ten-second-after-idle target rather than asserting it here.

Use the existing disposable fixture recipe in [CODE_GUIDE](../CODE_GUIDE.md#disposable-ui-smoke); do not mutate persistent sessions to verify this change. Current test owners and observed results belong to the integration handoff and [verification log](verification-log.md), not stale deleted-test rows or inferred success counts.
