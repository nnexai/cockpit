# Supervisor surface inventory

This is the current UI/source map and coverage-source inventory, not a record of checks run by this documentation update. [DECISIONS](../DECISIONS.md) owns normative authority rules; [CODE_GUIDE](../CODE_GUIDE.md) maps request flows and implementation owners. Earlier provenance, shipped defects and runtime observations live in the [verification log](verification-log.md) and [decision archive](../archive/decisions-log.md).

## Product surfaces

Tasks is the default view. Graph shows worker hierarchy; Dependencies shows canonical task prerequisites. Give work in the supervisor terminal; the dashboard is observational, with genuine decisions, guarded recovery and separate source Outcome, Integration and Cleanup.

### Current UI contract and source map

- **Tasks and attention:** Tasks opens by default. Read-only lanes show Queued, Starting, Working, Review and a collapsed Done disclosure (`accepted` in core). Initialized is diagnostic only. Cards show task identity, worker/subagent context, reported/observed provenance and literal failed-report text. Latest progress stays quiet; ordinary report bodies remain in details. Attention and Space filters dim rather than remove work. A compact Agents strip is available on wide, non-short Tasks layouts; Graph is a visible peer view.
- **One attention model:** [`attention.ts`](../src/app/supervisor/attention.ts) combines core attention and explicit local conditions. Genuine unresolved root questions are **Decide**, blocked/unknown recovery is **Recover**, and diagnostic/document notices are **Notice**. Routine worker implementation, questions, source review and integration coordination remain liaison-owned rather than user approvals. Causes retain provenance and real core age across queue rows, counters, summaries and badges; local-only rows do not invent timestamps.
- **Answer receipts:** Answers retain the exact current question link and delivery identity across uncertain outcomes; a newer question gets a separate scoped draft. Delivery and automatic transport ACK describe durable capture, not an Answer, model processing or resumed work. Details retain sender, delivery stage and timestamps. Only an explicit question-linked Answer addresses NeedsInput; fresh main evidence is separate. Worker questions remain liaison-owned, while recovery/offline conditions keep priority.
- **Queue:** [`SupervisorAttention.tsx`](../src/app/supervisor/SupervisorAttention.tsx) renders controlled disclosures and roving summary buttons. Counters explicitly focus the requested tier or open the attention overlay; polling does not move field focus. The inline queue is height-bounded and scrollable, including oversized expanded rows; its More indicator counts partially hidden rows. Narrow workareas and short windows use an overlay instead of squeezing the workarea.
- **Topology and Graph:** [`topology.ts`](../src/app/supervisor/topology.ts) builds Supervisor → canonical task → assigned worker relationships from `current_run_id` and explicit delegation/subagent parentage, never labels, Space location or a worker's `task_id` alone. Unassigned and nested workers remain represented; closed runs and completed tasks are omitted from Graph with a completed-task count. [`graphLayout.ts`](../src/app/supervisor/graphLayout.ts) deterministically lays out fixed 240×48 nodes with 32px column gaps and 56px row pitch, handling missing parents, cycles and deep chains iteratively. [`SupervisorGraph.tsx`](../src/app/supervisor/SupervisorGraph.tsx) owns the single graph scrollport, sticky column headings, named node/status/provenance anatomy, chain highlighting and optional internal subagents. Filters leave dimmed nodes keyboard-reachable.
- **Review-first details:** [`SupervisorActions.tsx`](../src/app/supervisor/SupervisorActions.tsx) presents Overview / Activity / Actions. Overview puts state, provenance, source Outcome, Integration, Cleanup and progress before the relationship path and task description. **Show in Tasks / Show in Graph** is local navigation only. Source acceptance requires a succeeded Result with SourceOutput bound to the exact result ID and current canonical task revision, not the launch-time task revision; target integration and resource removal are separate facts. Recovery tries reattachment first; unknown deliveries keep text and operation identity with no automatic replay or implied success.
- **Responsive layout and reveal:** [`useSupervisorLayout.ts`](../src/app/supervisor/useSupervisorLayout.ts) is the shared measurement model: workarea widths below 720px stack Tasks and use overlays; below 480px is compact; window heights at or below 600px use the attention overlay. Details use a resizable side panel on wide layouts, a resizable Graph sheet on narrow workareas at least 560px high, and an overlay otherwise. [`PanelSplitter.tsx`](../src/app/supervisor/PanelSplitter.tsx) supports pointer/keyboard resizing and reset. [`reveal.ts`](../src/app/supervisor/reveal.ts) minimally scrolls only the owning client scrollport, accounting for sticky headings and a Graph sheet. A visible node click preserves offsets. Tasks/Graph and lane offsets, disclosures, selection, filters, panel preferences and drafts are root-scoped in [`useSupervisorDrafts.ts`](../src/app/supervisor/useSupervisorDrafts.ts); restoration does not authorize mutations or focus a terminal.
- **Activity, diagnostics and archive:** [`SupervisorActivity.tsx`](../src/app/supervisor/SupervisorActivity.tsx) presents readable messages, operation receipts and annotations grouped by local day with actor attribution, stale-evidence marks and local task/run links. Native attachment, source and delivery records remain in Diagnostics. Closed tracking retains open descendants and truthful per-root task-count loading/unavailable states. [`useArchiveCounts.ts`](../src/app/supervisor/useArchiveCounts.ts) uses bounded concurrent snapshots and session/root/disclosure fences; **Updated** is not an invented closure time.
- **Authority and navigation:** Selecting, revealing, filtering or switching views never submits work or requests Herdr focus. Only explicit **Open terminal** uses fresh identity-fenced App navigation and focus acknowledgement. Private role credentials and attachment proof govern mutations, not focus or labels. Give work in the supervisor terminal; hide/return, offline transitions and recovery preserve relevant drafts and unknown-operation identity. Ordinary local worker tools and actual native children are autonomous within scoped work; this is not an OS sandbox.
- **Prerequisites and follow-ups:** [`SupervisorDependencies.tsx`](../src/app/supervisor/SupervisorDependencies.tsx), [`dependencies.ts`](../src/app/supervisor/dependencies.ts) and [`dependencyLayout.ts`](../src/app/supervisor/dependencyLayout.ts) keep canonical task dependencies separate from the worker hierarchy and nested steps. Accepted prerequisites remain visible, independent work remains runnable, and missing/invalid/cyclic prerequisites show affected-task reasons. Follow-up provenance is nonblocking, immutable and visible even for a removed source. Creation optionally waits on that source; scoped prerequisite edits retain drafts and task/document revisions.
- **Hierarchical steps:** [`SupervisorSteps.tsx`](../src/app/supervisor/SupervisorSteps.tsx) renders actual native checkboxes, leaf-derived mixed branch state/progress, local tree keyboard navigation, stable UUID rename/reparent/reorder/remove and explicit descendant previews. Numeric overflow remains readable with safe shrink/check actions, while malformed structure is read-only with unavailable progress. Destination ancestors reveal after a move, and same-UUID focus waits for the saved task revision/rendered destination without stealing later navigation. Removing a subtree chooses a surviving actual row, not a temporarily hidden descendant.
- **Protected task editing and uncertainty:** Description editing preserves reserved metadata and checklist bytes. A Working scope update fences both canonical task and document revisions and durably instructs the same current worker; worker self-refinement sends no self-message. Actual live native task children retain narrowed authority. Active prerequisite changes cannot insert unmet dependencies under a writer. Scoped drafts and unknown operations retain original task/root, UUID, payload and revisions; polling, navigation and failed delivery cannot clear or replay them. Explicit saved-state resolution is required.
