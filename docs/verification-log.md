## Original DECISIONS.md:147

- **Reference depth.** One `reference_depth` (API 0 to 5, `library_reference_depth_invalid` otherwise; UI `Follow references`: Off/1/2/3) replaces the boolean `hydrate_references` and the same-repository forge crawl, with no alias. Defaults: single Jira issue 1; forge issue/PR, new Jira query and any stored item or follow without the field 0 (additive `serde(default)`, no schema bump). Confluence page adds and space follows reject depth above 0; folders ignore it. References are Jira structured `parent`/`subtasks`/`links` frontmatter fields (chosen over a new `SourceAsset` field, which would touch every provider literal) plus Jira keys and URLs in description and comments and URLs in other bodies. A URL is followed only when it resolves under a configured provider instance (Jira, Confluence pages, GitHub/GitLab/Gitea issues and PRs) with the direct-import authority checks; reached items expand at the same depth by the same rules regardless of provider, and Confluence spaces, unsupported and unconfigured URLs stay links. Traversal (`SourceService::collect_related`, fetch-only) is breadth-first, deduplicated by canonical Library identity so cycles collapse, eight fetches in flight, at most 64 references per asset, with internal non-configurable caps: single import 32 related items/8 MiB/60 s, query follow 100/16 MiB/180 s. Seeds are saved before traversal; a failure, cap or cancel is a Partial row, never touches seeds and never authorizes a drop. Storage keeps one `included_by` reason per holder (shallowest route, relation, step); Details renders each distinct reason once (the UI deduplicates identical rendered reasons). Single import: depth persists on the seed and each explicit refresh re-traverses; related items get `Manual` plus a seed-held reason, so they survive seed removal and a complete refresh only strips the reason. Rejected: a new seed-held ref kind (the set only grows, like accumulate, and the boring model matches the old linked items). Query follow: related items get `Follow{F}` plus a follow-held reason; an item the query lists is a seed and drops the reason; a live follow drops unreached related items only after a complete related pass and complete listing, accumulate never does; unchanged seeds are traversed from stored `references`, and old seeds without them are refetched once. Space independence holds: refresh never fans out, Jira follows stay out of Spaces, a single add targeting a Space selects what that add saved.
